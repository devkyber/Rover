# 로그

`rover/teleop.py --log <파일>` 또는 `rover/record.py --log <파일>`이 남긴 CSV.
포맷과 컬럼 정의는 [`rover/logger.py`](../rover/logger.py), 해석 방법은
[`docs/03_튜닝과_NIS.md`](../docs/03_튜닝과_NIS.md).

자동 이름 규칙: `YYYY-MM-DD_HHMM_<태그>.csv`. 초기 수동 이름 로그는
`YYYY-MM-DD_<구성>_<상황>.csv` 형태도 남아 있다.

## 정지 로그가 특별한 이유

출발점 = 도착점이므로 **최종 위치가 곧 드리프트**다. 정답(ground truth)을
공짜로 얻는 유일한 상황이라, R 튜닝의 기준으로 쓴다.

```bash
python rover/replay.py logs/2026-09-06_4wheel_still.csv
```

## 공중 회전 로그를 튜닝에 쓸 수 없는 이유

바퀴 속도 관측은 "바퀴가 돌면 로버가 간다"를 가정한다. 공중에서는 그
가정이 거짓이므로 `wheel`·`nhc`의 NIS는 숫자가 예뻐도 의미가 없다.
`R_WHEEL_VELOCITY`는 **바닥에 내려놓고 실제로 굴린 로그**를 기다려야 한다.

## 줄자 정답의 범위

`2334`, `2347`에서 실제로 측정한 것은 **정지점의 종방향 거리**다. 정지점 사이
매 순간의 위치와 횡방향 위치는 외부 추적기로 측정하지 않았다. 따라서
`replay_gui.py`는 다음만 정답으로 취급한다.

- 줄자로 표시한 종방향 체크포인트
- 직진 기준선 `y=0` (로버 중심을 선 위로 주행했다는 가정)
- 체크포인트에 도착한 시각은 1초 이상 정지로 구분된 이동 구간의 끝

연속적인 실제 궤적은 이 로그만으로 복원할 수 없다. 모션캡처, 상부 카메라의
AprilTag 추적, 측량기 같은 **외부 위치 기준**이 있어야 한다.

새 시험의 기준점은 [`experiments.json`](experiments.json)에 기록한다.
`checkpoints_m`은 출발점을 포함해 각 장시간 정지점의 실제 `[x, y]`를 순서대로
쓴다. 예를 들어 1 m 정사각형은 다음과 같다.

```json
"ground_truth": {
  "label": "1 m square",
  "checkpoints_m": [[0, 0], [1, 0], [1, 1], [0, 1], [0, 0]],
  "tolerance_m": 0.05
}
```

각 변 끝에서 1초 이상 멈춰야 GUI가 체크포인트와 이동 구간을 자동 매칭한다.

## IMU 좌표계와 구형 로그

2026-09-11 이후 CSV에는 `imu_frame=body` 열이 있다. Arduino 드라이버가
`[x_body,y_body,z_body]=[-y_sensor,+x_sensor,+z_sensor]` 회전을 적용한 뒤 기록한다.
그 이전 로그에는 이 열이 없고 sensor frame 원시축이 들어 있다. 원본 파일은
수정하지 않고 `logger.replay()`가 구형 형식을 감지해 같은 회전을 한 번 적용한다.

따라서 CSV의 `ax,ay,az`를 직접 ESKF에 넣지 말고 반드시 `logger.replay()`를
사용한다. `replay_gui.py` 상단에는 구형 변환 적용 여부가 표시된다.
