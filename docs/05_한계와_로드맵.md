# 한계와 로드맵

> **이 시스템이 무엇을 못 하는지, 그리고 다음에 무엇을 할지.**
> 한 곳에만 적는다. 다른 문서에서 한계를 발견하면 여기로 링크한다.

---

## 1. 원리적 한계 — 코드를 고쳐도 안 없어진다

이건 버그가 아니라 **센서 구성이 정해진 순간 결정된 성질**이다.
근거는 [01 §9 관측가능성](01_이론_오도메트리와_ESKF.md).

### 1-1. yaw는 어디서도 관측되지 않는다 ★

중력은 수직축 정보를 못 준다(z축 회전은 중력 방향을 안 바꾼다).
현재는 gyro 적분만 상대 yaw를 만들고, 비방위 관측이 global yaw를 임의로
고치지 못하게 제한한다. 다음 wheel yaw-rate 관측도 slip 때문에 절대방위가
아니므로 **외부 heading 없이 장시간 방위를 고정할 수는 없다.**

**끊으려면 외부 기준이 필요하다** — 자력계(달에서는 무의미), 태양센서,
비전 랜드마크. 이게 P3 항목이 존재하는 이유다.

### 1-2. 자이로 바이어스는 정지 중에만 제거된다 ★★

ZARU가 유일한 수단이고, ZARU는 정지해야만 돈다.

| | 측정값 |
|---|---|
| LSM6DS3 실측 바이어스 | **3.7 °/s** |
| 정지 없이 20 s 주행 시 yaw 표류 | **약 41°** (`0.036 rad/s × 20 s`) |
| 5초 시작 정렬 + 주기적 정지 | `23:47` 로그 최종 yaw **+0.07°** |

> **미션 주행 프로파일에 주기적 정지가 필요하다.**
> 이건 선택이 아니라 이 IMU를 쓰는 대가다.
> `test_filter.py`의 시나리오 8(정지 있음)/9(정지 없음)이 이 사실을 고정한다.

BMI088로 바꾸면 완화되지만 **사라지지는 않는다.**

### 1-3. 위치 오차는 유계가 될 수 없다

`p`는 어떤 관측에도 등장하지 않는다(`H`의 `δp` 열이 전부 0). 위치는
속도의 적분일 뿐이다. **위치 관측이 없는 한 오차는 계속 자란다.**
할 수 있는 건 증가율을 낮추는 것뿐이다.

### 1-4. 가속도계 바이어스는 정지 중 기울기와 구분되지 않는다

`[0.1, 0, 9.8]`을 읽었을 때 "기울었다"인지 "x축 바이어스"인지
정지 상태에서는 원리적으로 알 수 없다. 가속해야 분리된다.

> 실무적 함의: **정지 로그만으로는 `ba`를 검증할 수 없다.**
> 중력 야코비안의 부호 오류가 오래 살아남은 이유가 이것이다
> ([03 §6.2](03_튜닝과_NIS.md)).

### 1-5. 센서 로그만으로 실제 연속 궤적을 만들 수 없다

ESKF가 만든 궤적은 **추정값**이지 정답이 아니다. 엔코더와 IMU를 다시
조합해 별도의 “true path”를 만들면 같은 센서 오차를 공유하므로 검증이 되지 않는다.

현재 실제 정답은 줄자로 표시한 일부 정지점뿐이다. `replay_gui.py`는 그 지점만
체크포인트 오차로 비교한다. 모든 시각의 실제 `x,y,yaw`가 필요하면 상부 카메라
AprilTag 추적, 모션캡처, 토탈스테이션 등 독립적인 외부 계측이 필요하다.

## 2. 현재 구현의 한계 — 고칠 수 있지만 아직 안 했다

| 한계 | 영향 | 어디 |
|---|---|---|
| **슬립 모델 없음** | 바퀴를 그대로 믿어 거리를 과대평가. 3 m 주행에서 10 % 슬립 → 약 0.3 m 오차 | `test_filter.py` 시나리오 7 |
| **`Present Current` 미사용** | 슬립·고착을 감지할 정보를 **읽고는 있는데 안 쓴다** | `logger.py`가 기록만 함 |
| **Chi-square 게이팅 없음** | 이상 관측(튀는 값)을 거르지 않는다 | `eskf._ekf_update` |
| **적응 R의 근거가 제한적** | 휠은 요레이트, 중력은 가속도 크기 편차로 완화하지만 지면/충격을 직접 구분하지 못함 | `eskf.model_wheel_velocity`, `model_gravity`, `model_nhc` |
| **리셋 야코비안 생략** | 주입 후 `P`에 `G = I − ½[δθ]ₓ`를 안 곱한다. 2차 효과 | `eskf._inject` |
| **시각동기 미보정** | IMU와 엔코더 사이 지연을 측정 안 함. 로그에 `imu_t`를 따로 남겨둔 이유 | `logger.py` |
| **NEES 미구현** | 시뮬에서 쓸 수 있는 더 강한 검정을 안 쓰고 있다 | — |
| **wheel yaw-rate 관측 없음** | gyro bias가 정지 사이에서 누적됨. 좌우 동일속도 직진 정보를 아직 안 씀 | `odometry.py` |
| **공개 pose는 wheel 속도 의존** | 연속이고 직선에 강하지만 wheel slip이면 거리도 그대로 틀림 | `Odometry.position` |
| **내부 ESKF `p`는 진단 전용** | 절대 위치 관측이 없어 pseudo-measurement cross-correction으로 점프 가능 | `Odometry.inertial_position` |
| **일정속도로 손에 들고 회전 시 정지 오인 가능** | 바퀴가 0이고 gyro 분산도 작으면 ZARU 조건을 만족할 수 있음 | `StillnessDetector` |

### 2-1. R은 어디까지 구했는가

| 값 | 현재 판정 |
|---|---|
| `R_WHEEL_VELOCITY=0.012` | **재검증 필요.** body-frame 수정 후 NIS 0.064~0.227/목표 1; 공개 pose 거리는 encoder 직접 적분 |
| `R_ZUPT=0.00014812` | **사용 가능, 재검증 중.** 새 모델 정지 NIS 1.50/목표 3, `23:47` 2.63 |
| `R_ZARU=0.00694874` | **사용 가능, 재검증 중.** 정지 NIS 1.68/목표 3; 주행 로그에서는 낮음 |
| `R_GRAVITY=0.02988870` | **동적 구간 미확정.** body-frame 수정 후 직선 NIS 0.99~2.05/목표 3 |
| NHC base/turn gain | **미확정.** 직진은 양호하지만 회전 외부 정답 없음 |
| wheel yaw-rate R | **미구현.** `B_eff`, 직진/회전/slip 실측 필요 |

좌표계와 출력 구조 수정에서는 R을 바꾸지 않았다. 직선 하나를 맞추기 위해 noise를 조작하지
않고, 같은 상수로 전 로그를 다시 계산해 모델 변화만 비교하기 위해서다. BMI088로
교체하면 센서 관련 Q/R과 정지 임계값은 전부 다시 측정한다.

## 3. 지금 당장 할 것 — 우선순위 순

### ✅ ① 시작 alignment + yaw 관측불가능 방향 보존

`23:47` 로그는 출발 전 yaw가 이미 `+3.13°`였고, 최종 `+5.14°`의 단계별
귀속은 `predict -6.89°`, 나머지 update 합계 `+12.03°`였다. Gravity가 직접
yaw를 측정하지 않는데도 `+5.39°`를 주입한 것은 R 미세조정 문제가 아니라
관측가능성 일관성 문제다.

구현 완료:

1. 연속 5초 정지 평균으로 `bg`와 gravity 기반 roll/pitch를 초기화한다.
2. 완료 시 position/velocity와 시작방향 yaw를 0으로 정의한다.
3. wheel/NHC/ZUPT/gravity의 Kalman gain에서 world-yaw 성분을 투영 제거하고
   quaternion 유한회전의 2차 yaw 변화도 정확히 복원한다.
4. 정렬 중 `teleop.py`는 모터에 0만 보내고 패널에 진행률을 표시한다.

Arduino sensor→body 축과 공개 pose 모델까지 수정한 `23:47` 결과는 최종 yaw
`+0.06°`, 복귀 `1.2 cm`, 최대 횡이탈 `0.4 cm`, 체크포인트 최대 `5.4 cm`다.
`23:34`는 복귀 `1.6 cm`, 체크포인트 최대 `4.1 cm`다. R은 바꾸지 않았으므로
직선을 만들기 위한 noise fitting 결과가 아니다. wheel yaw/slip 검증은 여전히 필요하다.

### ② wheel yaw-rate 관측 + 회전 ground truth ★★★

직진 로그로 `R_WHEEL_VELOCITY=0.012`를 맞췄고, 0.50 m 줄자 구간의 종방향
오차는 4 cm 이내다. 그러나 회전이 많은 로그는 wheel NIS 17, ZUPT NIS 29이고
실제 `x,y,yaw` 정답이 없다.

다음 시험은 치수를 잰 정사각형 코스와 제자리 `360°` 반복이다. 먼저 실제
`B_eff`를 구한 뒤 `ω_wheel=(v_R-v_L)/B_eff`를 약한 yaw-rate 관측으로 넣는다.
`v_L≈v_R`인 직진에서는 0 yaw-rate를 강하게 쓰되, 전류 비대칭·바퀴 분산·충격·
회전 slip이 있으면 R을 키운다. 더 강한 검증은 상부 카메라+AprilTag다.

### ③ 새 직진 반복 로그를 holdout으로 보관 ★★

현재 두 줄자 로그는 후보 선택 중 모두 확인했으므로 완전한 미사용 검증셋이 아니다.
같은 0.50 m 체크포인트 시험을 새로 한 번 찍고 **상수를 바꾸지 않은 채**
`replay_gui.py`로 오차를 확인한다. 허용오차는 우선 ±5 cm다.

### ✅ ④ 시뮬레이터 command 범위

공식 무부하 사양은 31 rpm이고 기본 `Velocity Limit(44)=135`의 command 환산은
`0.2023 m/s`다. 둘 다 **적재 실차 상한이 아니다.** 시뮬은 외측바퀴 최대
`0.1985 m/s`로 command 범위 안에 있고 테스트가 이를 고정한다. 실제 적재 지속
속도는 직선 full-command 로그의 정상상태 평균으로 별도 측정해야 한다.

### ⑤ Allan variance

정지 2시간 로그의 log-log 기울기에서 `Q` 계수 4개를 실측한다.
현재 `*_RANDOM_WALK` 두 개는 코드에 `placeholder`라고 적혀 있고,
잡음 밀도 두 개는 **BMI088 데이터시트 값인데 실제로는 LSM6DS3를 쓰고 있다.**

### ✅ 끝난 것

| | |
|---|---|
| `WHEEL_RADIUS_M` = 0.0625 m, `WHEELBASE_M` = 0.485 m | **실측 완료.** 단, skid-steer 회전용 `B_eff`는 별도 값이다 |
| 로그 자동 명명 | `logs/<날짜>_<시각>_<태그>.csv` — 덮어쓰기 불가능 |
| 4륜 방향·통신·100 Hz | 실기 검증 완료 |
| 직진 휠 R | `R_WHEEL_VELOCITY=0.012`, 줄자 로그로 확인 |
| 오프라인 재생 GUI | 차량 애니메이션, 동기 신호, NIS, 줄자 체크포인트 비교 |
| 시작 정렬 + 비방위 update yaw 보존 | 5초 정렬, `23:47` yaw `+5.14° → +0.07°` |
| 시뮬레이터 command 범위 검사 | 외측 최대 0.1985 m/s ≤ 기본 command 환산 0.2023 m/s |

## 4. 로드맵

> 원래 설계노트(문서 90)의 P0–P3 구조를 유지하되, **지금 실제 상태**로
> 갱신한 것이다.

### P0 — 없으면 나머지가 무의미

| | 항목 | 상태 |
|---|---|---|
| 1 | 로깅 + 오프라인 재생 파이프라인 | ✅ `record.py` → `replay.py` / `replay_gui.py` |
| 2 | 15-state ESKF + 휠 속도 + 중력 | ✅ |
| 3 | 물리 치수 캘리브레이션 | ✅ 실측 (62.5 mm / 485 mm) |
| 4 | Allan variance | ❌ §3-⑤ |
| 5 | 시작 정지 alignment | ✅ 5초 연속 정지, 조종 interlock 포함 |
| 6 | yaw 관측불가능 방향 보존 | ✅ wheel/NHC/ZUPT/gravity yaw correction 차단 |
| 7 | 시각동기 캘리브레이션 | ❌ (`imu_t` 로깅은 되어 있음) |
| 7a | IMU sensor→body extrinsic | ✅ Arduino 장착 회전 실측, 구형 로그 자동 변환 |
| 7b | 연속 wheel-inertial pose 출력 | ✅ 내부 strapdown `p`와 분리 |

### P1 — 정확도의 대부분이 여기서 나온다

| | 항목 | 상태 |
|---|---|---|
| 8 | NHC (측면 슬립 적응 R) | ✅ 구현, 직진 로그 확인 / 회전 정답은 없음 |
| 9 | ZUPT + ZARU | ✅ 발동률 95.8 % |
| 10 | "주기적 정차" 운용 규칙 | ⚠️ **문서화됨, 주행 프로파일에 미반영** |
| 11 | Chi-square 게이팅 | ❌ |
| 12 | 잔차 기반 적응 R (NHC 외) | ❌ |
| 12a | wheel yaw-rate + `B_eff`/slip 적응 R | ❌ 다음 실차 회전시험 |

### P2 — 차별화 포인트

| | 항목 | 상태 |
|---|---|---|
| 13 | 전류 기반 슬립/고착 검출 → 조종사 경고 + R 가중 | ❌ 데이터는 이미 있음 |
| 14 | 지형 분류 부산물 → CIV 매핑 재활용 | ❌ |

> 11번이 가성비가 가장 좋다. **전류를 이미 100 Hz로 읽어서 로그에
> 남기고 있는데 필터가 안 쓴다.** 배선도 센서도 추가로 필요 없다.

### P3 — 여유가 있으면

| | 항목 |
|---|---|
| 15 | 지면 광류 속도계(대지속도 직접 관측) 또는 stop-and-stare VO |
| 16 | 슬립비 상태 증강(15→24), ICR 온라인 추정, InEKF 승격 |
| 17 | **태양·광원 방위 기반 절대 yaw** — §1-1을 실제로 푸는 유일한 항목 |

## 6. 코드에 남은 부채

| | 왜 |
|---|---|
| `sim.py`의 슬립 모델 | 단순 배율. 실제 슬립은 지면·하중 의존 |
| `Q` 이산화 테스트 없음 | [F-02](07_실패기록.md#f-02)를 다시 넣어도 아무도 모른다 |
| 적재 실차 지속 최고속도 미측정 | 31 rpm은 24 V 무부하 사양일 뿐이다 |

> `gui_tuner.py`는 **삭제했다.** 시뮬 데이터로 슬라이더를 움직이는 방식은
> "실기 로그 + NIS"라는 이 리포의 튜닝 방법론과 충돌하고, 갱신 순서의
> 다섯 번째 사본이기도 했다 ([F-11](07_실패기록.md#f-11)).
