## 1. 무엇을 튜닝하는가

필터에는 **네 종류**의 숫자가 있고, 성격이 완전히 다르다.

| 종류 | 예 | 어떻게 정하나 |
|---|---|---|
| **물리 상수** | `WHEEL_RADIUS_M`, `WHEELBASE_M` | **자로 잰다.** 튜닝 대상이 아니다 |
| **`Q` (프로세스 잡음)** | `GYRO_NOISE_DENSITY` | Allan variance 또는 데이터시트 |
| **`R` (관측 잡음)** | `R_ZUPT`, `R_GRAVITY` | **NIS로 맞춘다** ← 이 문서의 주제 |
| **게이트/임계값** | `ZUPT_GYRO_STD_MAX` | 실측 로그의 최악값 바로 위 |

> **1번을 먼저 하지 않으면 나머지가 전부 무의미하다.**
> `WHEEL_RADIUS_M`이 10 % 틀리면 모든 거리가 10 % 틀리고,
> 필터는 그 오차를 `R`로 흡수하려고 엉뚱한 값에 수렴한다.
> 현재 `WHEEL_RADIUS_M=62.5 mm`, `WHEELBASE_M=485 mm`는 실측값이다.

### `Q`와 `R`의 의미

- **`Q`** = "내 예측 모델이 얼마나 틀리는가" (IMU 잡음)
- **`R`** = "이 센서를 얼마나 못 믿는가"

칼만 이득이 `K = P/(P+R)`이므로 ([01 §5.2](01_이론_오도메트리와_ESKF.md)),
둘의 **비율**이 필터의 행동을 결정한다. `Q`와 `R`을 똑같이 100배 해도
추정값은 거의 같고, 공분산 `P`만 100배가 된다.

**그래서 `Q`를 먼저 고정하고 `R`을 움직인다.** `Q`는 물리(센서 잡음)에서
오는 값이라 원칙적으로 측정 가능하고, `R`은 "이 관측이 얼마나 현실과
안 맞는가"라 상황 의존적이다.

## 2. 순서가 중요하다

```
1. 물리 치수 실측            ← 이게 없으면 아래가 전부 헛수고
2. 정지 로그 20초 녹화
3. 정지 판정 임계값 설정      ← 실측 최악값 기준
4. Q 설정                    ← Allan variance (미완) 또는 데이터시트
5. R을 NIS로 튜닝            ← 관측 하나씩
6. 주행 로그로 R_WHEEL/NHC   ← 직진 완료, 회전 정답은 없음
7. 독립 반복 + 정사각형 주행으로 드리프트 실측
```

지금은 **6번의 직진 구간까지** 끝났고, 7번이 다음이다.

## 3. NIS — 정답 없이 필터를 판정하기

### 3.1 문제

시뮬레이터에서는 참값을 아니까 "얼마나 틀렸나"를 바로 잰다.
**실제 로버 로그에는 참값이 없다.** 그럼 필터가 잘 돌고 있는지 어떻게 아나?

### 3.2 착상

필터는 매 갱신마다 두 가지를 내놓는다.

1. **혁신(innovation)** `y = z − h` — 예측이 실제로 얼마나 빗나갔나
2. **혁신 공분산** `S = HPHᵀ + R` — 얼마나 빗나갈 거라고 스스로 주장했나

> **NIS는 이 둘을 비교한다.**
> "네가 틀릴 거라고 말한 만큼 실제로 틀렸는가?"

이건 참값을 전혀 요구하지 않는다. 필터 자신의 숫자만 쓴다.
**그래서 실제 주행 로그에 쓸 수 있다.** 이게 NIS의 존재 이유다.

### 3.3 정의

```
NIS = yᵀ S⁻¹ y
```

필터가 일관적(consistent)이면 `y ~ N(0, S)`이므로 이 값은
**자유도 m의 카이제곱 분포**를 따른다. `m`은 관측의 차원이다.

카이제곱 분포의 평균은 자유도와 같으므로:

> **평균 NIS는 관측 차원 `m`에 가까워야 한다.**

| 관측 | `m` | 목표 평균 NIS |
|---|---|---|
| 휠 속도 | 1 | 1 |
| NHC | 2 | 2 |
| ZUPT | 3 | 3 |
| ZARU | 3 | 3 |
| 중력 | 3 | 3 |

### 3.4 읽는 법

| 관측 결과 | 뜻 | 조치 |
|---|---|---|
| **평균 NIS ≫ m** | `S`가 너무 작다 = **과신(overconfident)**. 실제로는 더 많이 틀리는데 안 그럴 거라고 우기는 중. 새 정보를 거부하기 시작하고, 심하면 발산 | 그 `R`을 **올린다** |
| **평균 NIS ≪ m** | `S`가 너무 크다 = **소심(too timid)**. 믿어도 될 관측을 버리고 있다. 안전하지만 정확도 손해 | 그 `R`을 **내린다** |
| 평균 NIS ≈ m | 필터의 자기 평가가 정직하다 | 둔다 |

**관측 종류별로 따로 봐야 한다.** 보통 다섯 개 중 하나만 거짓말을 한다.
그래서 `eskf._record()`가 이름별로 모으고 `replay.py`가 나눠서 낸다.

```bash
python rover/replay.py ../logs/2026-09-06_4wheel_still.csv
```

## 4. 판정 기준은 얼마나 엄격해야 하나

"m에 가깝다"는 애매하다. 카이제곱 분포로 정확한 신뢰구간을 낼 수 있다.
`N`개 샘플의 평균은 `χ²(Nm)/N`을 따르므로 95 % 구간은:

```python
from scipy.stats import chi2
lo, hi = chi2.ppf(0.025, N*m)/N, chi2.ppf(0.975, N*m)/N
```

| `m` | `N` | 95 % 구간 |
|---|---|---|
| 3 | 100 | 2.54 – 3.50 |
| 3 | 1000 | 2.85 – 3.15 |
| 3 | 2000 | **2.89 – 3.11** |

### 그런데 이 구간을 그대로 쓰면 안 된다

위 식은 **샘플이 독립**이라고 가정한다. 우리 NIS 샘플은 100 Hz로 뽑히고,
연속한 두 샘플은 거의 같은 상태에서 나온다. **강하게 자기상관되어 있다.**

실측 (정지 로그, `1 + 2Σρ_k`로 유효표본수 계산):

| 관측 | 샘플 `N` | 상관 팽창계수 | **유효 `N_eff`** | 독립가정 구간 | 실제 구간 |
|---|---|---|---|---|---|
| zupt | 1917 | 46.1 | **42** | 2.89–3.11 | **2.30–3.79** |
| zaru | 1917 | 58.0 | **33** | 2.89–3.11 | **2.22–3.89** |
| gravity | 1996 | 4.2 | **475** | 2.89–3.11 | **2.78–3.22** |
| nhc | 83 | 18.4 | 5 | 1.59–2.45 | 0.60–4.23 |
| wheel | 83 | 33.2 | 3 | 0.72–1.33 | 0.05–3.36 |

**유효 표본이 1917개가 아니라 42개다.** 20초 로그는 보이는 것만큼 많은
정보를 담고 있지 않다.

여기서 배울 것:

1. **독립가정 구간으로 판정하면 멀쩡한 필터를 계속 기각하게 된다.**
2. `wheel`·`nhc`는 `N_eff`가 3~5라 **어떤 판정도 의미가 없다.** 정지
   로그에서 이 둘의 NIS를 보고 뭔가 결론 내리면 안 된다.
3. 그래서 `replay.py`는 엄밀한 구간 대신 **실용적인 3배 규칙**
   (`ratio > 3` 과신, `< 0.33` 소심)을 쓴다. 느슨하지만 자기상관에
   강건하고, 진짜 문제(수십~수백 배 어긋남)는 확실히 잡는다.

> 로그가 길수록 `N_eff`가 커져 판정이 날카로워진다. 20초로 대충 맞추고,
> 확정은 더 긴 로그로.

## 5. 실제 튜닝 절차

### 5.1 원칙

> **한 번에 하나씩 바꾸고, 매번 다시 측정한다.**

`R`들은 독립이 아니다. 전부 같은 상태를 갱신하므로 서로 영향을 준다.
실측으로 확인한 결합(세 개를 함께 스케일):

```
 배율    zupt   zaru   grav
 x0.40    1.47  12.25  11.63     ← 발산 방향
 x0.60    1.42   6.73   5.42
 x1.00    1.75   3.48   2.16     ← 여기가 공동 최적
 x1.50    2.21   2.11   1.07
```

**`zupt`은 배율에 거의 반응하지 않는데 `zaru`·`gravity`는 크게 움직인다.**
공통 배율 하나로는 셋을 동시에 맞출 수 없다. 관측별로 따로 해야 한다.

### 5.2 좌표하강 (실제로 쓴 방법)

각 `R`을, **자기 자신의** 평균 NIS가 자기 자유도에 오도록 조정하고,
순서대로 돌면서 수렴할 때까지 반복한다.

```
iter 1  zupt 2.93  zaru 3.33  grav 3.27  | drift 5.3 mm
iter 2  zupt 2.93  zaru 3.33  grav 3.27  | drift 5.3 mm   ← 이미 수렴
```

**한 번 만에 수렴하고 더 안 움직인다.** 세 관측이 서로를 크게 밀지 않는
좋은 지점이라는 뜻이다.

재현:

```bash
cd rover
python replay.py ../logs/2026-09-06_4wheel_still.csv
# 가장 나쁜 항목 하나를 골라 config.py에서 그 R만 수정 → 다시 실행
```

### 5.3 어느 방향으로 얼마나?

**직관과 달리 `NIS ∝ 1/R`이 아니다.** 실측 (`R_ZUPT`만 변경, 수정 전 필터):

```
 R_ZUPT 배율   평균 NIS
   x0.25        6.04
   x0.50        5.41
   x1.00        5.20   ← 최솟값
   x2.00        5.58
   x4.00        6.86
   x16.0       16.93
```

**U자 곡선이다.** `R`을 줄이면 `S`가 작아져 NIS가 오를 것 같지만, 동시에
필터가 관측을 더 세게 믿어 상태를 더 강하게 잡아당기므로 혁신도 작아진다.
두 효과가 반대라서 **최솟값이 생긴다.**

실무적 함의:

- **한 방향으로 계속 밀어도 목표에 못 갈 수 있다.** 최솟값이 목표보다
  높으면 그 초과분은 `R`의 문제가 아니라 **`Q`가 작거나 모델이 틀린 것**이다.
- 그러므로 **양쪽으로 시험해봐야 한다.** 한 방향만 보면 잘못된 결론에 간다.

### 5.4 `Q`를 건드리면 어떻게 되나

```
 Q 배율    zupt   zaru   gravity
  x1.00     5.20   4.80    4.61
  x2.00    60.00   5.06   78.35
  x4.00    53.18   5.30   220.58
  x16.0     3.71   5.63   134.63
```

**`Q`는 훨씬 난폭하다.** 2배만 해도 gravity NIS가 4.6 → 78로 뛴다.
`Q`는 `P` 전체를 키워 모든 관측에 동시에 영향을 주기 때문이다.

> **`Q`는 튜닝 손잡이가 아니다.** 센서의 물리적 성질이므로
> **Allan variance로 측정해야** 한다. 그때까지는 데이터시트 값을 고정해두고
> `R`만 만진다. (`config.py`의 `*_RANDOM_WALK`는 아직 `placeholder`다.)

## 6. 튜닝할 때 지켜야 할 네 가지

전부 **실제로 당해서** 알게 된 것이다. 사건 기록은
[07 실패 기록](07_실패기록.md)에 있고, 여기에는 규칙만 적는다.

### 6.1 데이터가 그 파라미터를 관측하지 못하면 튜닝하지 않는다

정지 로그에서 휠 관측은 83회, **유효표본 3개**다. `replay.py`가
"lower R_WHEEL"이라고 말해도 그 말은 근거가 없다.
공중에서 바퀴만 돌린 로그는 더 나쁘다 — "바퀴가 돌면 로버가 간다"는
가정 자체가 거짓이라 필터가 **유령 0.428 m**를 만들어낸다.

> 이 규칙 때문에 정지/공중 로그는 버리고 바닥 줄자 로그에서만
> `R_WHEEL_VELOCITY`를 정했다. 회전 NHC는 외부 정답이 생길 때까지 보류한다.
> → [F-22](07_실패기록.md#f-22) · [F-23](07_실패기록.md#f-23)

### 6.2 관측 불가능한 방향은 성능 지표로 검증되지 않는다

중력 야코비안의 `∂y/∂δba` 부호가 틀려 있었는데 드리프트 차이는
**0.07 mm**였다. 정지 상태에서 가속도계 바이어스는 기울기와 원리적으로
구분되지 않기 때문이다.

> 성능이 아니라 **수식을 검사한다.** `test_filter.py`의 1층이
> 모든 `H`를 수치미분과 대조한다. → [F-04](07_실패기록.md#f-04)

### 6.3 모델을 바꾸면 이전 튜닝은 무효다

위 부호를 고치자 NIS가 통째로 이동했다 (gravity 2.40 → 2.16, zupt 2.58 → 1.75).
`R`은 **그 모델에 대해** 맞춰진 값이다.

> 필터 수식을 건드렸으면 **반드시 재튜닝.** → [F-06](07_실패기록.md#f-06)

### 6.4 한 번의 실행을 성능으로 읽지 않는다

단일 시드 0.577 m vs 10시드 최악 1.498 m — **2.6배** 차이다.
그리고 시뮬 잡음이 실기보다 3.4배 조용하면 그 통과는 아무 의미가 없다.

> `test_filter.py`는 **10시드 몬테카를로, 최악값 판정**이고,
> `sim.py` 잡음은 실측값이다. → [F-24](07_실패기록.md#f-24) · [F-25](07_실패기록.md#f-25)

## 7. NEES — 정답이 있을 때

시뮬레이터에서는 참 상태를 아니까 더 강한 검정을 할 수 있다.

```
NEES = (x_true − x̂)ᵀ P⁻¹ (x_true − x̂)
```

평균이 상태 차원(우리는 15)에 가까워야 한다.

| | 필요한 것 | 검사하는 것 |
|---|---|---|
| **NIS** | 없음 | 관측 예측이 정직한가 |
| **NEES** | 참 상태 | **추정 오차 전체**가 정직한가 |

NEES가 더 강하다. NIS가 통과해도 NEES가 실패할 수 있다 — 관측되지 않는
방향(우리의 yaw, `ba`)에서 과신하는 경우가 그렇다.

**그러나 NEES는 실기 로그에 쓸 수 없다.** 그래서 실전 도구는 NIS이고,
NEES는 시뮬레이터 전용이다. (아직 구현 안 함 — 향후 작업.)

정지 로그에는 **공짜 정답이 하나 있다**: 출발점 = 도착점이므로
**최종 위치가 곧 드리프트**다. `replay.py`가 이걸 자동으로 판정한다.

```
Log is stationary throughout, so final position IS the
drift: 0.0053 m  [GOOD]
```

## 8. 현재 값과 근거

### 기존 튜닝값과 구조 변경 후 상태

| 상수 | 값 | 변경 전 평균 NIS | 목표 | 근거 |
|---|---|---|---|---|
| `R_ZUPT` | 0.00014812 | **2.93** | 3 | 좌표하강 |
| `R_ZARU` | 0.00694874 | **3.33** | 3 | 좌표하강 (최초 추측 0.0001에서 약 70배) |
| `R_GRAVITY` | 0.02988870 | **3.27** | 3 | 좌표하강 (최초 추측 0.1에서 하향) |

이 값은 2026-09-06 당시 모델에서 정지 20초 드리프트 **5.3 mm**, ZUPT 95.8 %를
만들었다. 이후 시작 정렬과 yaw correction projection이 추가됐으므로 값은 그대로
유지하되 **확정값으로 부르지 않는다.** 새 모델로 같은 정지 로그를 재생한 NIS는
ZUPT 1.50, ZARU 1.68, gravity 0.45(각 목표 3)다. 앞의 둘은 3배 실무범위 안이고,
gravity는 너무 낮지만 주행에서는 1.0–10.2로 바뀌므로 base R 하나만 낮추면 안 된다.

### 실측 임계값 (정지 판정)

관측된 최악값 바로 위로 잡았다. 데이터시트 추정이 아니다.

```python
ZUPT_GYRO_STD_MAX  = 0.030   # 실측 최악 0.0236
ZUPT_ACCEL_STD_MAX = 0.250   # 실측 최악 0.1475
```

> **BMI088로 바꾸면 훨씬 조용하므로 전부 다시 측정해야 한다.**

### 저속 직진 튜닝 완료, 동적 구간 재검증 필요

| 상수 | 이전 | 현재 | 근거 |
|---|---|---|---|
| `R_WHEEL_VELOCITY` | 0.05 (추측) | **0.012** | 줄자 구간 종방향 오차 ≤4 cm |
| `R_WHEEL_TURN_GAIN` | — | **0.1** | 스키드 스크럽 |
| `R_GRAVITY_ACCEL_GAIN` | — | **1.0** | gravity NIS 210 → 3.1 |

**현재 값이 물리적으로 타당한 근거와 아직 남은 검증**

1. `2334`와 `2347`의 서로 다른 거리 패턴에서 종방향 오차가 비슷하게 작았다.
   다만 후보 선택 과정에서 두 로그를 모두 열어봤으므로 `2347`을 엄밀한
   **미사용 holdout**이라고 부를 수는 없다. 새 반복 주행이 독립 검증 데이터다.
2. **`R`의 하한을 독립적으로 실측했다.** 바퀴 상호 불일치 0.0007 m/s,
   고주파 산포 0.0014 m/s, 양자화 0.0015 m/s. `R`은 센서 잡음이 아니라
   **모델 오차**(줄자 기준 2.5~4 %)를 덮는 값이고 0.012는 둘 다 위에 있다.
3. **줄자와 NIS가 독립적으로 같은 방향을 가리켰다.** 0.05에서 NIS는
   "ok"였지만 줄자는 −22 %였다 — NIS만으로는 편향을 못 본다는 것도
   같이 배웠다 ([F-27](07_실패기록.md#f-27)).

현재 필터로 `replay_gui.py`가 체크포인트를 2D 비교하면 `2347`의 0.5/1.0/1.5 m
오차는 **0.8/3.7/5.4 cm**, 최종 복귀 오차는 **1.1 cm**다. `2334`의 전체
체크포인트 최대오차는 **4.1 cm**다. 이 결과는 sensor→body 회전과 연속 pose
출력 수정 뒤의 값이며, R은 바꾸지 않았다.
단, 당시 실제 횡방향 위치를 따로 재지 않았으므로 이것은 “로버 중심이 기준
직선 위에 있었다”는 가정과의 차이다. 연속 실제 궤적과 횡방향 진짜값은 외부
추적기가 있어야 검증할 수 있다.
