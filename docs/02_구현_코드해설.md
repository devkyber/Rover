# 코드 해설 — 식에서 실행 흐름까지

원리는 [ESKF 이론](01_이론_오도메트리와_ESKF.md), 첫 예제는 [회전각 수업](09_turn_angle_lesson.md).
이 문서는 코드를 읽는 지도다. 현장 명령은 [README](../README.md)에만 둔다.
기존 긴 Replay GUI 설명은 [문서 아카이브](archive/README.md)에 있다.

## 1. 데이터가 흐르는 길

```text
IMU raw counts ── imu_reader ── gyro/accel, 축·단위·시간 ─┐
바퀴 레지스터 ── dxl_reader ── 위치/회전율/전류 ────────────┤
                                                         ▼
                              rover_main → Odometry.step
                                             ├─ ESKF 자세·bias
                                             ├─ 바퀴 속도 + 자세 → 공개 위치
                                             ├─ CSV + metadata
                                             └─ telemetry → station 화면
station DRIVE → drive.js → link.js → station_link → motors → dxl_control
USB H.264 → camera.py → /video → video.js → 화면
```

센서 입력, 추정, 모터 출력, 표시를 나눠 읽는다. 숫자의 원본은
[config.py](../rover/config.py), 호출 순서는 [odometry.py](../rover/odometry.py)다.

## 2. 먼저 단위·축·shape를 적는다

| 값 | 단위 / shape | 주의점 |
|---|---|---|
| `gyro`, `accel` | rad/s, m/s² / `(3,)` | body frame; accel은 중력을 제거한 값이 아님 |
| `bg`, `ba` | rad/s, m/s² / `(3,)` | 추정 bias; 입력에서 두 번 빼지 않음 |
| `q` | `[w,x,y,z]` / `(4,)` | body → world 회전 |
| `P` | `(15,15)` | 오차 상태의 공분산. nominal quaternion은 4개지만 회전 오차는 3개 |
| wheel `vel` | rad/s | 좌우 부호와 바퀴 반지름을 적용해야 m/s |
| `dt`, `imu_dt` | s | 실제 사용한 적분 간격; accel sensor clock과 구분 |

`R @ vector`는 행렬 곱, `a * b`는 NumPy에서 성분별 곱이다.
`state['bg']`는 dictionary에서 bias array를 꺼내는 표현이다.

## 3. eskf.py 읽는 순서

[eskf.py](../rover/eskf.py)에서 다음 함수를 순서대로 찾는다. 줄 번호보다 함수명을 쓴다.

| 함수 | 따라갈 계산 | 스스로 확인할 것 |
|---|---|---|
| `create_state()` | 위치·속도·쿼터니언·bias·공분산 생성 | nominal 16개, error 15개인 이유 |
| `quat_multiply`, `quat_to_rot` | 회전 합성과 벡터 변환 | 곱 순서를 바꾸면 같은 회전인가? |
| `predict()` | bias 제거 → 명목값 적분 → F/Q → 공분산 전파 | `(rad/s) × s = rad`; 정지에서 +g와 world −g가 상쇄되는가? |
| `model_wheel_velocity()` | 바퀴 관측과 예측 h, Jacobian H, noise R | 실제로 어떤 속도 성분을 관측하는가? |
| `_ekf_update()` | 잔차 y → S → K → Joseph 공분산 갱신 | 표준편차와 분산을 혼동하지 않았는가? |
| `_inject()` | 오차 상태를 명목값에 반영 | 회전을 벡터 덧셈으로 처리하지 않는 이유 |
| `model_gravity/nhc/zupt/zaru()` | 각 관측의 가정과 잔차 | 정지/접지/중력 가정이 언제 깨지는가? |
| `get_euler_deg()` | quaternion에서 표시 각도 추출 | yaw ±180°와 누적 회전의 차이 |

`_ekf_update(... preserve_yaw=True)` 경로도 읽는다. heading 관측이 아닌 update가
공분산 교차항으로 yaw를 바꾸지 않도록 처리하지만, 그것이 외부 heading 정보를 만들어내지는 않는다.
자세한 행렬 유도는 [이론 7·8장](01_이론_오도메트리와_ESKF.md#7-예측-단계--전체-유도).

## 4. Odometry.step 한 cycle

[odometry.py](../rover/odometry.py)의 중심은 `step()`이다.

1. 바퀴 속도·IMU로 정지 여부를 판정하고 startup alignment를 모은다.
2. 준비되면 gyro prediction을 수행한다. BMI088 batch가 있으면 모든 frame을 순서대로 처리한다.
3. wheel·ZUPT/ZARU·gravity·NHC 중 조건에 맞는 update를 적용한다. **정확한 순서와 gate는 함수 본문을 따른다.**
4. 바퀴 평균 속도를 자세로 world frame에 회전하고 공개 위치를 적분한다.
5. `snapshot()`으로 화면·기록에 쓸 값을 꺼낸다.

공개 위치의 개념식은 다음과 같다.

```text
v_forward = mean(wheel_angular_rate × side_sign × wheel_radius)
v_world = R(q_ESKF) × [v_forward, 0, 0]
p_public += v_world × dt
```

`Odometry.position`과 내부 `state['p']`는 다른 출력이다.
`filter_pos`는 내부 strapdown 진단 값이므로 화면의 위치와 혼동하지 않는다.

## 5. IMU·로그 경계

[imu_reader.py](../rover/imu_reader.py)는 raw count를 SI 단위로 바꾸고 센서별 mounting map을 적용한다.
BMI088 gyro FIFO에는 frame별 timestamp가 없으므로 host batch 간격에서 시각을 추정한다.
동일한 400 Hz 설정만으로 accel/gyro 동기화가 증명되지는 않는다.

[logger.py](../rover/logger.py)는 CSV와 metadata를 저장한다. 기존 이름을 덮어쓰지 않는다.
구형 Arduino sensor-frame 로그는 `replay()`의 변환을 거친다.
재현에는 당시 치수·설정·소스가 필요하며, 최신 코드가 과거 설정을 자동 복원하지는 않는다.
관련 원본과 한계는 [로그 목록](../logs/README.md), 센서 구현 근거는 [Jetson](11_jetson_bringup.md).

## 6. 조이스틱에서 바퀴까지

[drive.js](../station/web/drive.js)는 키보드·화면 패드·게임패드 입력을 정규화한다.
[main.js](../station/web/main.js)와 [link.js](../station/web/link.js)를 거쳐 drive 메시지가 전송된다.
[station_link.py](../rover/station_link.py)는 메시지·명령 age를 관리한다.
[rover_main.py](../rover/rover_main.py)는 명령을 읽고 [motors.py](../rover/motors.py)를 통해 속도를 쓴다.

모터 Goal Velocity는 마지막 값을 유지할 수 있다. 그래서 정상 경로뿐 아니라
읽기 실패·명령 timeout·예외·종료 경로를 따라가야 한다. 소프트웨어 정지와 모터 측 watchdog은
다르며, 실제 freeze/kill/bus 단절 검증은 [SAFE-01](05_한계와_로드맵.md#safe-01)에 남아 있다.
학습 중 live 제어 루프를 breakpoint로 멈추지 않는다.
