## 1. 필터 구조: 직접 EKF 말고 **Error-State KF (ESKF/MEKF)** 권장

제안서엔 "EKF"라고만 되어 있는데, 자세를 상태에 넣는 순간 오일러각 EKF는 짐벌락·선형화 오차로 손해임.
문헌 흐름은 명확히 ESKF → invariant EKF (InEKF) 방향:

- ESKF: 공칭상태(quaternion 등)는 IMU로 적분하고, KF는 **작은 오차상태만** 추정 → 선형화 오차 최소, 자코비안이 단순.
- InEKF/PIEKF: 오차동역학이 상태에 무관해져 일관성(consistency)이 좋아짐. 보행/휠 로봇에서 EKF가 시간 지나면 성능이 무너지는 이유가 "예측상태로 테일러 전개하는 선형화"라고 지적됨.

**권장:** 15-오차상태 ESKF로 시작 (한 학기 안에 디버깅 가능한 규모), 여유되면 InEKF로 승격.

```
공칭 상태:  p(3)  v(3)  q(4)  b_g(3)  b_a(3)
오차 상태:  δp(3) δv(3) δθ(3) δb_g(3) δb_a(3)   → 15×15 P
확장 후보:  s_L, s_R (좌/우 유효 반경 스케일)      → 17
            x_ICR, y_ICRl, y_ICRr (skid-steer ICR) → 20
            i_1..i_4 (바퀴별 종방향 슬립비)         → 24
```

### 1.1 2단 구조 (제안서의 400 Hz / 100 Hz 분리와 정합)

```
[400 Hz]  자세 서브필터 — 자이로 적분 + 중력벡터 보정(roll/pitch) + 자이로 바이어스
              └ 조종사 디스플레이에 바로 송출 (지연 최소화, 전복 한계 판단용)
[100 Hz]  전체 ESKF — 위 자세를 예측에 쓰고, 아래 3장의 관측량들로 보정
[ 1-5 Hz] (옵션) VO / 루프클로저 — 저주파 보정
```
자세만 400 Hz로 빼는 이유: 조종사 UI의 tilt 표시는 **지연이 정확도보다 중요**하고,
100 Hz 융합필터의 반복/게이팅 로직이 여기서 지터를 만들면 조종 감이 나빠짐.

## 2. 예측 모델

IMU 스트랩다운(등속 아님):
```
p ← p + v·dt + ½(R(a_m − b_a) + g)dt²
v ← v + (R(a_m − b_a) + g)dt
q ← q ⊗ Exp((ω_m − b_g)dt)
b_g, b_a ← random walk
```
Q는 **Allan variance로 실측해서** 채울 것 (BMI088 datasheet 값은 시작점일 뿐).
필요한 4개 계수: 자이로 ARW, 자이로 바이어스 랜덤워크, 가속도 VRW, 가속도 바이어스 랜덤워크.
→ 정지 상태 2~3시간 로그 한 번이면 끝. **이거 안 하면 R/Q 튜닝이 영원히 삽질됨.**

> 대안: 모래지형에서 IMU 적분이 불안하면 "IMU를 관측량으로 쓰는" 운동학 예측 모델(엔코더 예측 + IMU 보정)도 가능.
> 하지만 슬립 상황에서 예측이 오염되므로, **IMU 예측 / 엔코더 관측** 방향을 권장함.

## 3. 관측량 메뉴 — 여기가 진짜 브레인스토밍

### 3.1 휠 오도메트리 속도 관측 (기본)
바디프레임 종방향 속도 `v_x^b = (r/4)Σω_i` (또는 좌우 평균), yaw rate `ω_z = (r/B_eff)(ω_R−ω_L)`.
- 위치가 아니라 **속도**를 관측량으로 넣을 것 (위치를 넣으면 슬립 오차가 누적되어 필터가 끌려감).
- `B_eff` (유효 윤거)는 skid-steer에서 기하학적 윤거와 다름 → 캘리브레이션 필수 (5.2).

### 3.2 NHC (Non-Holonomic Constraint) — 가성비 1위
바퀴가 옆으로 미끄러지지 않는다면 `v_y^b = 0`, `v_z^b = 0`.
공짜 관측량 2개가 100 Hz로 들어옴 → 위치 드리프트가 극적으로 줄어듦.
**단, skid-steer는 회전 시 원리적으로 측면 슬립이 있으므로** `R_vy`를 |ω_z|의 함수로 부풀릴 것:
```
R_vy = σ0² + (κ · |ω_z|)²      # 제자리 선회 중엔 사실상 NHC 끔
```

### 3.3 ZUPT / ZARU — **이 프로젝트에서 가장 저평가된 카드**
정지 중이면 `v = 0` (ZUPT), `ω = 0` (ZARU) 를 pseudo-measurement로 주입.
ZARU는 **자이로 바이어스를 직접 관측**하게 해줘서 yaw 드리프트를 근본적으로 잡음.

행성 로버 문헌(arXiv 1906.08849)이 정확히 이걸 함: 주기적 정차 시 zero-type 구속을 넣어
**연산량 큰 visual 보정의 빈도를 낮추면서도** 정확도를 유지.

우리 임무 시나리오는 정지가 이미 강제로 들어있음 —
**해머 4회 타격**, **스카우트 사출**, 조종사 판단 정지, 실린더 전개.
→ 운용 규칙으로 **"30초/5 m 마다 1.5초 완전 정지"** 를 넣으면 사실상 공짜로 정확도를 산다.
정지 판정: `|a_m|−g` 분산 + 자이로 분산 + **모터 목표속도=0 + 엔코더 Δ=0** (지령을 알고 있으므로 오탐이 거의 없음).

### 3.4 중력벡터 roll/pitch 보정
`|‖a_m‖ − g| < ε` 이고 `‖ω‖` 작을 때만 수용하는 게이트를 걸고 중력 방향 업데이트.
제안서의 "roll·pitch 절대 추정으로 드리프트 배제"가 이것. 모래 위 저속 주행이라 게이트가 자주 열림.

### 3.5 yaw 문제 — 정면으로 다뤄야 함
모함에 자력계가 없으므로 **heading은 자이로 적분 + ZARU가 전부**. 대략적 오차 예산:
- ARW 기여: BMI088 자이로 노이즈밀도 ~0.014 °/s/√Hz → 45분에 σ ≈ 0.7° 수준 (무시 가능)
- **바이어스 드리프트 기여가 지배적**. 잔류 바이어스 0.01 °/s가 남으면 45분에 **27°**.
→ ZARU로 바이어스를 자주 재추정하면 수 도 수준으로 억제 가능. **온도 드리프트 주의**(주행 중 발열).

선택지:
1. **ZARU 강화** (비용 0, 1순위)
2. **자력계 추가** — DYNAMIXEL 4개의 영구자석과 수십 A 전류 옆이라 매우 불리. 스카우트가 겪는 문제(제안서 2.6)와 동일하지만 모함은 훨씬 심함. 마스트 끝(카메라 팬축 위)에 올리면 가능성은 있으나 팬 각도 보상 필요. **비추천~조건부**
3. **태양/광원 방위 센서** — 대회장이 실내면 조명 방향, 실외면 태양. 광각 카메라 프레임에서 최대 밝기 방향을 방위 기준으로 쓰는 초저비용 트릭. 절대 yaw를 몇 도 수준으로 고정 가능. **실험해볼 가치 있음**
4. **비전 yaw** (3.8)
5. 운용적 해법: 조종사 UI에 "마지막 ZARU 이후 경과시간 + 추정 yaw 불확실도"를 띄우고, 커지면 정차 유도

### 3.6 잔차 기반 적응 R — 제안서 문구의 실제 구현
제안서: "잔차로 슬립 구간 엔코더 가중치 자동 감소". 두 가지를 같이 쓸 것.

**(a) Chi-square 게이팅** — 이상치 컷
```
d² = yᵀ S⁻¹ y ,  S = HPHᵀ + R
d² > χ²(dof, 0.99)  → 그 업데이트 기각 또는 R ×= (d²/χ²)
```
**(b) 혁신 기반 적응 (covariance matching / Sage-Husa)** — 슬라이딩 윈도우 N개 혁신으로
```
Ĉ = (1/N)Σ yᵢyᵢᵀ  ,  R̂ = Ĉ − HPHᵀ   (양정치 투영 + EMA 스무딩)
```
주의: R̂만 믿으면 "지속 슬립"에서 필터가 슬립을 정상으로 학습해버림(발산).
→ **R에 상한/하한을 걸고**, 물리 기반 슬립 지표(3.7)와 AND 조건으로 쓸 것.

### 3.7 모터 전류 기반 슬립 감지 — 우리 하드웨어가 이미 갖고 있는 무기
Ojeda·Borenstein 계열(Current-Based Slippage Detection, IEEE T-RO)의 핵심:
슬립이 시작되면 **견인력이 무너지면서 전류가 떨어지는데 바퀴 속도는 유지/증가**한다.
DYNAMIXEL X-시리즈는 `Present Current`를 Sync Read로 축별로 읽을 수 있으므로 **바퀴별** 지표가 만들어짐.

지표 후보:
```
r_i = ω_i − f(I_i, pitch, v̂)        # 전류-속도 정합 잔차 (f는 사전 캘리브레이션 곡선)
disagree = Var(ω_1..ω_4)            # 바퀴 간 불일치
a_mismatch = d/dt(v_wheel) − a_x^IMU  # 엔코더 가속 vs IMU 가속
```
`slip_score = w1·|r| + w2·disagree + w3·|a_mismatch|` → `R_wheel = R0·(1 + α·slip_score²)`

부가 효과 (조종사에게 그대로 값어치 있음):
- **고착(immobilization) 검출**: 전류 高 + 속도 ≈ 0 + 지령 有 → 파묻힘. 즉시 경고 + 오도메트리 완전 정지.
  행성 로버 실패의 전형적 시나리오이고, 미검출 고착은 위치추정을 완전히 망가뜨림.
- **지형 분류**: 전류/슬립 통계로 모래 vs 자갈 vs 암반 → **CIV 매핑의 사전정보로 재사용** (임무 가치 ↑)

### 3.8 비전 — 언제, 어떻게 쓸 것인가
MER/MSL 방식: **VO는 상시가 아니라 "필요할 때만"** (슬립 위험 구간, 정차 후). 우리도 동일 전략 권장.

문제점 정리:
- 팬 서보 위 단일 카메라 → 외부파라미터가 시변. **VO 구간에는 팬을 고정**하거나 서보 각도를 외부파라미터에 주입.
- 모노 → 스케일 불확실. 다만 휠/IMU가 스케일을 주므로 **회전(특히 yaw) 관측용으로만 써도 가치 있음**.
- 달·모래 아날로그 지형은 저텍스처·반복 패턴·강한 그림자 → 특징점 VO가 잘 깨짐(문헌 다수 지적).

대안 아이디어(가성비 순):
1. **지면 지향 광류 "비주얼 속도계"** — 아래를 보는 초소형 카메라 + LED, 프레임 간 상호상관으로
   **실제 대지속도**를 직접 관측 → 슬립비를 직접 측정. 특징점이 필요 없어 모래에서 오히려 잘 됨.
   질량 ~10 g. **3 kg 예산 안에서 가장 수익률 높은 추가 센서 후보.**
2. **정지 중 VO만 (stop-and-stare)**: 어차피 ZUPT용으로 서는 김에, 정차 전후 프레임으로 상대 변위 계산.
   실시간 부담 0, 실패해도 안전.
3. cuVSLAM/Isaac ROS — Orin Nano에서 GPU 가속으로 돌아가지만 **스테레오 전제**가 강함. 카메라 1대 추가 = 질량·대역폭 협상 필요.

### 3.9 접지 평면 구속
4륜이 모두 접지 중이면 바퀴 접점 4개가 이루는 평면 ≈ 지형면.
서스펜션/바디 각도와 결합해 `v_z^b = 0`을 넘어 **국소 경사 추정**까지 가능 → 3D 자세 표시와 CIV 매핑 좌표 품질에 기여.

### 3.10 이벤트 기반 위치 앵커
스카우트 착지 좌표는 지상노드가 궤적 역산으로 산출함(제안서 II-4). 모함이 그 지점까지 이동해 해머 타격을 하므로,
"모함이 도달한 지점 = 산출된 착지 좌표 부근"이라는 **약한 위치 관측**을 만들 수 있음.
정확도는 낮지만 (수십 cm~m) **긴 주행 후 위치 드리프트의 발산은 막아줌**. 공분산 크게 주고 넣을 것.
같은 지점 재방문 시 카메라 이미지 매칭으로 루프 클로저를 만드는 것도 동일 계열.

## 4. 슬립을 "상태로" 넣을 것인가, "R로" 처리할 것인가

| 방식 | 장점 | 단점 | 권장 |
|---|---|---|---|
| 적응 R (제안서 방식) | 단순, 안정, 15-state 유지 | 슬립량 자체는 모름, 지속 슬립에 약함 | **1단계 채택** |
| 슬립비 상태 증강 (i_1..i_4, random walk) | 슬립량 추정 → CIV/지형 데이터로 재활용 | 관측성 확보 필요(IMU 가속 or 대지속도계) | 2단계 |
| ICR 파라미터 온라인 추정 | skid-steer 회전 모델 정확도 ↑ | 파라미터 커플링, 튜닝 난이도 | 2단계 |
| IMM (정상/슬립/고착 3모드) | 이산 상황 전환에 강함 | 구현·튜닝 비용 3배 | 여유 시 |

**로드맵:** 적응 R + NHC + ZUPT/ZARU 로 먼저 완주 → 필드 로그 확보 → 그 로그로 슬립비 증강 버전을 오프라인 비교.

## 5. 구현 실무 — 여기서 프로젝트가 실제로 깨진다

### 5.1 타이밍 / 시각동기 (최우선 리스크)
- RS-485에서 4축 `Present Position/Velocity/Current`를 100 Hz로 읽어야 함.
  → **Sync Read (가능하면 Fast Sync Read) + 보레이트 최대치**. 축별 개별 read 절대 금지 (지연 누적).
  → 실제 왕복시간을 먼저 측정할 것. 100 Hz 여유 없으면 엔코더만 100 Hz, 전류는 20~50 Hz로 분리.
- IMU와 엔코더의 **상수 지연 차**를 캘리브레이션: 제자리 선회 시
  엔코더 유래 `ω_z`와 자이로 `ω_z`의 **상호상관 지연 피크**를 찾아 보정. (수십 ms만 어긋나도 회전 시 위치오차가 급증)
- 모든 샘플에 **수집 시점 타임스탬프**를 붙여 로그. 사후 재처리 가능해야 튜닝이 됨.

### 5.2 캘리브레이션 체크리스트
1. IMU Allan variance (Q 산출) — 정지 로그 2h+
2. IMU 정렬(가속도계 오프셋/축 비직교) + **IMU→바디 장착 회전** (수평면 정치)
3. 유효 바퀴 반경 r (직진 10 m 왕복, 지면별로 다름 — 모래/자갈 각각)
4. 유효 윤거 B_eff (제자리 360° ×N, 자이로 적분값 기준으로 역산)
5. 전류-속도-경사 f 곡선 (경사대 + 정속 주행, 슬립 없는 조건에서)
6. 카메라 내부/외부 + 팬 서보 각도 ↔ 카메라 회전 매핑

### 5.3 소프트웨어 구성
- **오프라인 우선**: Jetson은 로그만 남기고, 필터 개발/튜닝은 PC에서 동일 로그로 반복 재생.
  → "필드에서 튜닝"은 대회 일정상 불가능. 9월 목표는 **로그 파이프라인 + 재생기**여야 함.
- 언어: 프로토타입 Python(numpy) → 검증 후 C++ 이식. 15-state ESKF는 Orin에서 100 Hz가 전혀 부담 아님.
- 베이스라인: `robot_localization`의 `ekf_localization_node` 를 **이겨야 할 기준선**으로 한 번 돌려볼 것
  (ROS2 도입 여부와 별개로, 우리 필터가 그보다 못하면 뭔가 틀린 것).
- 워치독 연동: 제안서의 100 ms 미수신 → 토크 차단. 이때 **필터는 죽이지 말고 ZUPT 모드로 전환**할 것.

### 5.4 검증 계획 (10월 필드테스트에 그대로 투입)
| 시험 | 목적 | 성공 기준(제안) |
|---|---|---|
| 정지 2시간 | Allan / 바이어스 안정도 | Q 계수 산출 |
| 직진 10 m ×5 (평지/모래) | 스케일, 종방향 드리프트 | 종방향 오차 < 2 % |
| Figure-8 20 m | yaw 드리프트 + 커플링 | 최종 위치오차 < 5 % 경로장 |
| 제자리 360° ×10 | B_eff, yaw 스케일 | yaw 오차 < 5° |
| 경사대 0~25° 정지 | roll/pitch 절대 정확도 | < 1° |
| **모래 슬립 시험** (인위적 슬립 유도) | 슬립 검출률 / 적응 R 동작 | 슬립 구간 검출 > 90 %, 미검출 시 대비 위치오차 개선 |
| 고착 시험 (바퀴 들기) | immobilization 검출 | < 0.5 s 내 경고 |
| 45분 임무 모사 | 최종 드리프트 | ATE 목표를 여기서 확정 |

지상 진실값(ground truth): 총국(total station)이 없으면 **바닥 AprilTag 그리드 + 천장/삼각대 카메라**가 현실적.
최소한 줄자 + 마킹으로 시작점/종점 오차라도 정량화할 것.

## 6. 우선순위 제안 (9~10월 일정 기준)

**P0 — 이거 없으면 나머지 무의미**
1. 로깅 + 오프라인 재생 파이프라인, 시각동기/지연 캘리브레이션
2. Allan variance, r / B_eff 캘리브레이션
3. 15-state ESKF + 휠 속도 관측 + 중력 roll/pitch

**P1 — 정확도의 대부분이 여기서 나옴**
4. NHC (측면 슬립 적응 R 포함)
5. ZUPT + ZARU + 운용 규칙("주기적 정차")
6. Chi-square 게이팅 + 적응 R

**P2 — 차별화 포인트**
7. DYNAMIXEL 전류 기반 슬립/고착 검출 → 조종사 경고 + R 가중
8. 지형 분류 부산물 → CIV 매핑에 재활용 (임무 서사와 연결됨)

**P3 — 여유 있으면**
9. 지면 광류 속도계(대지속도 직접 관측) 또는 stop-and-stare VO
10. 슬립비 상태 증강 / ICR 온라인 추정 / InEKF 승격
11. 태양·광원 방위 기반 절대 yaw

## 7. 제안서 대비 보완이 필요한 지점 (심사/발표에서 찔릴 수 있는 곳)

1. **yaw 절대 기준이 없다** — 제안서엔 "roll·pitch는 중력으로 절대 추정"이라고만 되어 있고 yaw는 언급 없음.
   질문 들어오면 "ZARU + 주기적 정차로 바이어스를 재추정해 45분 임무 내 드리프트를 X° 이하로 관리"라고
   **수치로 답할 수 있게** 오차 예산표를 준비할 것.
2. **"잔차로 가중치 감소"의 발산 위험** — 지속 슬립에서 적응 R이 슬립을 정상으로 학습하는 실패모드.
   물리 지표(전류/IMU 가속 불일치)와의 AND 조건을 설명에 넣으면 방어됨.
3. **100 Hz 융합의 실현 가능성** — 병목은 연산이 아니라 **RS-485 Sync Read 왕복시간**. 실측치를 확보해둘 것.
4. **비전이 오도메트리에 안 들어감** — 현재 카메라는 조종 시야 전용. 이건 "의도적 설계 선택(저텍스처 지형에서
   특징점 VO 신뢰 불가, 대신 관성-엔코더-전류 3중 융합)"으로 포지셔닝하는 편이 더 강함.
