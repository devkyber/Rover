## 1. 표기와 좌표계

### 좌표계

| 기호 | 이름 | 정의 |
|---|---|---|
| `{W}` | 월드 (world) | 시작 지점에 고정. **z가 위쪽.** 중력은 `g_world = [0,0,−9.81]` |
| `{B}` | 바디 (body) | 로버에 고정. **x 전진, y 좌측, z 위쪽** (ROS REP-103) |

`R` 은 **월드 ← 바디** 회전행렬이다. 즉 바디 좌표의 벡터 `u`를 월드로
옮길 때 `R u`. 반대는 `Rᵀ`.

> 이 방향을 헷갈리면 부호가 전부 뒤집힌다. 기억법: `R`의 열은 바디
> 축들을 월드에서 본 것이다.

### 실제 Arduino 센서 프레임

센서의 XYZ와 로버의 XYZ는 이름이 같아도 같은 축이 아니다. 2026-09-06 세 주행
로그에서 엔코더 종방향 가속과 IMU 축의 상관을 측정한 결과, sensor Y와의 상관은
`-0.76~-0.82`이고 기울기는 `-1.02~-1.11`이었다. sensor X 상관은 `0.01~0.06`뿐이다.
따라서 현재 장착 변환은 다음과 같이 실측 확정했다.

```
[x_body]   [ 0 -1  0] [x_sensor]
[y_body] = [ 1  0  0] [y_sensor]
[z_body]   [ 0  0  1] [z_sensor]
```

즉 로버 전방은 sensor `-Y`, 좌측은 sensor `+X`, 위는 sensor `+Z`다. 이 행렬은
직교이고 determinant가 `+1`인 순수 90° 회전이다. accel과 gyro에 똑같이 적용한다.
ESKF에 들어가는 모든 벡터는 이 변환을 마친 **body frame**이어야 한다.

### 쿼터니언

`q = [w, x, y, z]`, **스칼라 우선**. 단위 쿼터니언이며 `R = R(q)`.
`⊗`는 쿼터니언 곱.

### 상태

| 기호 | 크기 | 뜻 | 단위 |
|---|---|---|---|
| `p` | 3 | 월드 위치 | m |
| `v` | 3 | 월드 속도 | m/s |
| `q` | 4 | 자세 (월드←바디) | — |
| `bg` | 3 | 자이로 바이어스 | rad/s |
| `ba` | 3 | 가속도계 바이어스 | m/s² |

명목상태(nominal)는 4+3×4 = **16개 숫자**지만, 쿼터니언은 자유도가 3뿐이라
오차상태(error state)는 **15개**다. 이게 ESKF의 출발점이다 (§6).

### 자주 쓰는 연산

**반대칭 행렬(skew)**: `[u]ₓ v = u × v`

```
        ⎡  0   −u₃   u₂ ⎤
[u]ₓ =  ⎢  u₃   0   −u₁ ⎥
        ⎣ −u₂   u₁   0  ⎦
```

성질: `[u]ₓᵀ = −[u]ₓ`, `[u]ₓ v = −[v]ₓ u`. 두 번째 항등식을 아래에서
계속 쓴다.

## 2. 오도메트리란 무엇인가

**오도메트리 = 추측항법(dead reckoning).** 외부 기준 없이, 자기가 얼마나
움직였는지를 계속 더해서 현재 위치를 안다.

```
위치(t) = 위치(0) + ∫ 속도 dt
```

이게 전부다. 그리고 여기에 이 분야의 핵심 성질이 있다:

> **Uncorrected bias accumulates through integration. Odometry alone does not
> guarantee bounded long-term position or heading error.**

For a constant velocity bias `ε`, the position error after `T` seconds is `εT`.
Individual errors can cancel, and informative measurement updates can reduce
uncertainty; error does not necessarily increase at every sample. An external
position reference such as GNSS can constrain drift while reliable measurements
are available, but does not guarantee error bounds in all conditions.

그래서 오도메트리 설계의 목표는 "오차 없애기"가 아니라 **오차 증가율
낮추기**이고, 실제 작업은 대부분 다음 둘이다.

1. **편향(bias)을 없앤다** — 편향은 시간에 비례해 쌓이지만, 백색잡음은
   `√T`로만 쌓인다. 편향 제거가 압도적으로 중요하다.
2. **공짜 정보를 최대한 쓴다** — "지금 안 움직인다", "옆으로는 못 간다"
   같은 구속조건은 센서 없이 얻는 관측이다 (§8).

우리 시스템에서 이 둘은 각각 **ZARU**와 **NHC/ZUPT**로 나타난다.

### 왜 두 센서를 융합하는가

| | 잘하는 것 | 못하는 것 |
|---|---|---|
| **엔코더** | 저속·정지에서 정확, 편향 없음 | 슬립하면 통째로 거짓말. 자세를 모름 |
| **IMU** | 자세·가속 변화에 즉각 반응, 슬립 무관 | 편향이 적분되어 폭주 |

두 센서의 실패 방식이 **상관되어 있지 않다**. 이게 융합이 이득인 이유다.
바퀴가 헛돌 때 IMU는 "가속이 없다"고 말하고, IMU가 표류할 때 바퀴는
"속도는 이만큼"이라고 말한다.

## 3. 휠 오도메트리

### 3.1 엔코더에서 속도까지

XH430은 Present Velocity를 **0.229 rev/min 단위**로 준다.

```
ω_wheel [rad/s] = raw × 0.229 × 2π / 60
v_wheel [m/s]   = ω_wheel × r          (r = 바퀴 반지름)
```

> `r`은 **실측해야 한다.** 이 한 숫자가 모든 거리에 곱해진다.
> `r`이 10 % 틀리면 주행거리가 10 % 틀리고, 그 위에서 한 R 튜닝은
> 전부 무효다. 현재 섀시의 값은 `config.WHEEL_RADIUS_M = 0.055 m`다
> (2026-09-06 로그를 기록한 이전 섀시는 0.0625 m).

### 3.2 차동구동 기구학

좌/우 바퀴 속도 `v_L`, `v_R`, 트랙폭(좌우 바퀴 간격) `b`:

```
전진속도   v = (v_R + v_L) / 2
요레이트   ω = (v_R − v_L) / b
```

유도는 간단하다. 로버가 순간중심 주위로 각속도 `ω`로 돈다면 좌우 바퀴는
반지름이 `b/2`만큼 다르므로 속도차가 `ωb`가 된다.

### 3.3 4륜 스키드스티어는 다르다

우리는 조향축이 없다. **바퀴를 옆으로 끌면서(scrub) 돈다.**

그 결과 위 `ω` 식은 지면·하중·스크럽에 따라 편향된다. 흔히 실효 트랙폭이
기하학적 `b`보다 커서 회전율을 과대평가하지만, 이를 모든 지면의 법칙으로
가정해서는 안 된다.

현재 1단계 코드에서는 바퀴 yaw rate를 아직 관측으로 쓰지 않는다.
gyro가 실제 몸체 회전을 직접 읽고, 바퀴 모델은 아직 실효 트랙폭 검증이 없기 때문이다.

```python
# Non-heading updates preserve global yaw.
# Steering yaw comes from bias-corrected gyro integration.
```

**현재는 요레이트는 자이로, 바퀴는 전진속도를 담당한다.** 다음 단계에서는
`ω_wheel=(v_R-v_L)/B_eff`를 독립적인 약한 관측으로 추가한다. 좌우 속도가 같으면
이상적인 무슬립 모델에서 `ω_wheel=0`이므로 직진 gyro drift를 제한할 수 있다.

다만 `v_L=v_R`이 실제 직진을 보장하는 것은 아니다. 바퀴 반지름·정렬·하중·마찰이
좌우에서 다르거나 한쪽이 미끄러지면 같은 encoder 속도에서도 몸체는 돈다. 따라서
이를 `yaw=0` 강제식으로 쓰지 않고, 다음 조건에서만 작은 `R`을 주는 관측으로 쓴다.

- 네 바퀴 속도 분산이 작다.
- 좌우 전류 비대칭과 slip 징후가 작다.
- 큰 충격이나 급회전 구간이 아니다.
- 실측 회전시험으로 구한 `B_eff`를 사용한다.

### 3.4 위치가 아니라 속도를 관측으로 쓰는 이유

바퀴 **위치**(적분값)를 관측으로 쓰면, 한 번 슬립한 오차가 그 뒤 모든
관측에 영원히 실려 온다. **속도**를 쓰면 슬립은 그 순간의 잘못된 관측
하나로 끝나고, 다음 샘플부터 정상으로 돌아온다.

그래서 `update_wheel_velocity()`는 속도를 관측한다. 로그에 위치도 남기지만
그건 진단용이다.

### 3.5 실제로 공개하는 위치: wheel-inertial pose

현재 로버에는 절대 위치 센서가 없다. 따라서 15-state ESKF의 내부 `p`는
속도·기울기 관측의 cross-covariance로 순간 보정될 수 있다. 수학적으로 가능한
posterior correction이지만, 실제 차체가 순간이동한 것처럼 보이는 odometry 출력에는
부적합하다. 외부에 공개하는 연속 pose는 다음 물리 모델로 적분한다.

```
v_body = [v_wheel, 0, 0]
v_world = R(q_ESKF) v_body
p_odom(k+1) = p_odom(k) + v_world dt
```

따라서 엔코더가 평행이동 크기, ESKF가 roll/pitch/yaw와 gyro bias를 담당한다.
yaw를 0으로 고정하지 않는다. 실제 회전이면 gyro가 `q_ESKF`를 돌리고 경로도 곡선이
된다. 단, 바퀴가 미끄러지면 `v_wheel` 자체가 틀리므로 pose도 틀린다. 이는 광류,
비전 또는 다른 대지속도 관측이 생기기 전까지 남는 원리적 한계다.

## 4. 관성항법 — IMU 단독은 왜 실패하는가

### 4.1 센서 모델

```
gyro_raw  = ω_true + bg + n_g
accel_raw = Rᵀ(a_world + g_up) + ba + n_a       (g_up = [0,0,+9.81])
```

가속도계는 **비력(specific force)** 을 잰다. 가속도가 아니다. 가만히
놓으면 중력을 버티는 수직항력을 느껴 **`+g`(위쪽)를 읽는다.** 자유낙하하면
0을 읽는다. 이 부호를 틀리면 필터가 완전히 뒤집힌다.

> 확인법: 평평하게 놓았을 때 `az ≈ +9.81`이면 맞다.
> 우리 로그: `az = 9.70` ✓

### 4.2 잡음의 두 종류

| 이름 | 기호 | 성질 | 위치오차 기여 |
|---|---|---|---|
| 백색잡음 (noise density) | `σ` [단위/√Hz] | 매 샘플 독립 | `√T`로 증가 |
| 바이어스 랜덤워크 | `σ_b` [단위/s/√Hz] | 천천히 떠돎 | `T^1.5`로 증가 |
| **고정 바이어스** | `b` | 상수 | **`T²`로 증가** |

세 번째가 지배적이다. 그래서 **바이어스 추정이 이 필터의 존재 이유**다.

이 계수들을 실측으로 얻는 표준 방법이 **Allan variance**다 (수 시간 정지
로그의 log-log 기울기에서 5개 계수를 읽는다). 우리는 아직 안 했고,
`config.py`의 `*_RANDOM_WALK`는 `placeholder`라고 적혀 있다.

### 4.3 왜 적분만으로는 안 되는가 — 숫자로

자이로 바이어스 `b_g`가 있으면 자세 오차는 `δθ = b_g·T`로 자란다.
기울기 오차 `δθ`는 중력을 잘못 분해해 **가짜 수평가속** `g·sin(δθ) ≈ g·δθ`
를 만든다. 이걸 두 번 적분하면:

```
위치오차 ≈ ½ · g · b_g · T³ / 3 = g·b_g·T³/6
```

우리 IMU의 `b_g = 3.7 °/s = 0.065 rad/s`를 넣으면:

| T | 위치오차 |
|---|---|
| 1 s | 0.1 m |
| 10 s | **106 m** |
| 60 s | 23 km |

**10초에 100 m.** IMU 단독 항법이 왜 불가능한지 이보다 명확할 수 없다.
필터가 하는 일은 이 `b_g`를 추정해서 빼는 것이고, 그게 ZARU다 (§8.5).

### 4.4 기울기 1도의 무게

```
9.81 × sin(1°) = 0.17 m/s²
```

이걸 6초 적분하면 **3 m**다. 자세 오차 1도가 위치 오차 3 m다.
그래서 중력 업데이트(§8.4)가 roll/pitch를 잡아주는 게 중요하고,
그래서 회전 중에 그걸 잘못 쓰면 (원심력을 기울기로 오인) 재앙이 된다.

## 5. 베이즈 필터에서 칼만 필터까지

### 5.1 베이즈 재귀

우리가 원하는 건 관측들이 주어졌을 때 상태의 사후분포
`p(x_k | z_1:k)`다. 마르코프 가정 하에 이건 두 단계로 쪼개진다.

```
예측:  p(x_k | z_1:k−1) = ∫ p(x_k | x_k−1) p(x_k−1 | z_1:k−1) dx_k−1
갱신:  p(x_k | z_1:k)   ∝ p(z_k | x_k) · p(x_k | z_1:k−1)
```

일반적으로 이 적분은 못 푼다. **모든 것이 선형이고 모든 잡음이
가우시안이면** 사후분포가 가우시안으로 유지되고, 평균과 공분산만 따라가면
된다. 그게 칼만 필터다.

### 5.2 칼만 필터

선형 모델 `x_k = F x_{k−1} + w`, `z = H x + n`, `w ~ N(0,Q)`, `n ~ N(0,R)`:

**예측**
```
x⁻ = F x
P⁻ = F P Fᵀ + Q
```

**갱신**
```
y = z − H x⁻              혁신 (innovation)
S = H P⁻ Hᵀ + R           혁신 공분산
K = P⁻ Hᵀ S⁻¹             칼만 이득
x  = x⁻ + K y
P  = (I − K H) P⁻
```

**칼만 이득의 의미.** `K = P Hᵀ (HPHᵀ + R)⁻¹`를 스칼라로 보면
`K = P / (P + R)`이다.

- `P ≫ R` (내 예측이 형편없다) → `K → 1` → 관측을 그대로 믿는다
- `P ≪ R` (센서가 형편없다) → `K → 0` → 관측을 무시한다

**즉 `R`은 "이 센서를 얼마나 안 믿는가"의 단위 있는 표현이다.**
튜닝(03 문서)이 하는 일이 정확히 이 저울을 맞추는 것이다.

### 5.3 Joseph form

`P = (I − KH)P`는 수학적으로는 맞지만 부동소수점에서 **대칭성과 양정치성을
잃는다.** 한 번 잃으면 필터가 발산한다. 대신:

```
P = (I − KH) P (I − KH)ᵀ + K R Kᵀ
```

두 항 모두 구조적으로 대칭·양반정치라서 안전하다. 연산이 조금 더 들지만
100 Hz에서 15×15는 아무것도 아니다. 우리 `_ekf_update()`가 이걸 쓴다.

### 5.4 EKF와 그 한계

모델이 비선형이면 현재 추정점에서 **1차 테일러 전개**로 선형화한다:
`F = ∂f/∂x`, `H = ∂h/∂x`. 이게 EKF다.

한계는 명확하다.

1. **선형화 오차**가 그대로 필터 오차가 된다. 오차가 크면 전개점이
   나쁘고, 나쁜 전개점은 더 큰 오차를 낳는다 (발산).
2. **`P`는 진짜 오차를 모른다.** 계산된 `P`가 실제 오차보다 작으면
   필터는 과신(overconfident)하고 새 정보를 거부한다. 이걸 **일관성
   (consistency)** 문제라 하고, 검사 도구가 NIS다 ([03 문서](03_튜닝과_NIS.md)).
3. **쿼터니언은 그냥 못 넣는다.** `q`는 4개 숫자인데 자유도는 3이다.
   `q + K y`를 하면 단위 노름 제약이 깨지고, 공분산은 특이(singular)해진다.

3번을 정면으로 푸는 게 ESKF다.

## 6. 왜 EKF가 아니라 ESKF인가

**핵심 아이디어: 상태를 두 조각으로 나눈다.**

```
참값  =  명목값  ⊞  오차
x_true =   x    ⊞   δx
```

- **명목값(nominal)** `x`: 크고, 비선형이고, 쿼터니언을 포함한다.
  IMU로 그냥 적분한다. 칼만 필터를 거치지 않는다.
- **오차(error)** `δx`: 작고, 15차원 벡터이며, **회전도 3-벡터 `δθ`로
  표현된다.** 칼만 필터는 오직 이것만 다룬다.

`⊞`(injection)는 덧셈이되 자세만 쿼터니언 곱이다:

```
p ⊞ δp = p + δp        (v, bg, ba 도 동일)
q ⊞ δθ = q ⊗ exp(δθ)
```

### 이게 사주는 것 세 가지

1. **차원 문제가 사라진다.** 오차 자세는 3-벡터이므로 `P`는 15×15로
   정칙(non-singular)이다. 단위 노름 제약이 없다.

2. **선형화가 정확해진다.** `δθ`는 설계상 항상 작다 (매 갱신마다 명목값에
   주입하고 0으로 리셋하므로). 작은 각도에서는 `exp(δθ) ≈ [1, δθ/2]`가
   거의 정확하고, 2차 이상 항이 진짜로 무시할 만하다. EKF의 1번 한계가
   구조적으로 완화된다.

3. **자코비안이 단순해진다.** 뒤에 나오는 `F`와 `H`들이 전부 상수이거나
   `skew()` 한 번짜리인 이유다.

### 오차의 정의 — 국소(local)냐 전역(global)이냐

여기가 부호를 틀리기 가장 쉬운 지점이다. 두 관례가 있다:

| 관례 | 정의 | `δθ`가 사는 곳 |
|---|---|---|
| 국소 (local / body) | `q_true = q ⊗ δq` | **바디 프레임** |
| 전역 (global / world) | `q_true = δq ⊗ q` | 월드 프레임 |

**이 코드는 국소 관례를 쓴다.** `_inject()`가 `q ⊗ δq`를 하기 때문이다:

```python
state['q'] = quat_normalize(quat_multiply(state['q'], dq))
```

아래 모든 `F`, `H`는 이 관례에서 유도된 것이다. 관례를 섞으면 부호가
뒤집히고, 증상은 "이유 없이 조금씩 나빠짐"이라 잡기 매우 어렵다.
그래서 `test_filter.py`가 `_inject`와 같은 `⊞`로 수치미분을 해서
**관례가 일치하는지까지** 검사한다.

## 7. 예측 단계 — 전체 유도

### 7.1 명목값 적분 (스트랩다운)

```
a_world = R (accel_raw − ba) + g_world          g_world = [0,0,−g]

p ← p + v·dt + ½ a_world dt²
v ← v + a_world dt
q ← q ⊗ exp((gyro_raw − bg)·dt)
bg, ba ← 변화 없음                (랜덤워크: 평균은 그대로, 불확실성만 증가)
```

정지·수평 확인: `accel_raw = [0,0,g]`, `ba=0`, `R=I`
→ `a_world = [0,0,g] + [0,0,−g] = 0` ✓

### 7.2 오차 동역학

`x_true = x ⊞ δx`를 참 방정식에 넣고 1차 항만 남기면 (국소 관례):

```
δṗ = δv
δv̇ = −R [a]ₓ δθ − R δba + n_a
δθ̇ = −[ω]ₓ δθ − δbg + n_g
δḃg = n_bg
δḃa = n_ba
```

여기서 `a = accel_raw − ba`, `ω = gyro_raw − bg` (바이어스 제거된 값).

**`δv̇`의 첫 항이 어디서 오는가.** 자세가 `δθ`만큼 틀리면 회전행렬이
`R(I + [δθ]ₓ)`이 되고, 가속도의 월드 성분이
`R(I+[δθ]ₓ)a − Ra = R[δθ]ₓ a = −R[a]ₓ δθ`
만큼 틀어진다 (마지막 등호가 §1의 `[u]ₓv = −[v]ₓu`).

**즉 자세 오차가 속도 오차를 낳고, 속도 오차가 위치 오차를 낳는다.**
§4.3의 `T³`가 이 사슬이다.

### 7.3 이산화 — `F` 행렬

`F = I + A·dt` (1차):

```
        δp     δv      δθ        δbg     δba
δp   ⎡  I    I·dt      0          0       0    ⎤
δv   ⎢  0     I    −R[a]ₓ·dt      0     −R·dt  ⎥
δθ   ⎢  0     0    I−[ω]ₓ·dt   −I·dt      0    ⎥
δbg  ⎢  0     0       0           I       0    ⎥
δba  ⎣  0     0       0           0       I    ⎦
```

코드와 1:1로 대응한다:

```python
F[0:3, 3:6]   = np.eye(3) * dt
F[3:6, 6:9]   = -R @ skew(accel) * dt
F[3:6, 12:15] = -R * dt
F[6:9, 6:9]   = np.eye(3) - skew(gyro) * dt
F[6:9, 9:12]  = -np.eye(3) * dt
```

### 7.4 `Q` 이산화 — 실제로 틀렸던 부분

잡음밀도 `σ`의 단위는 **단위/√Hz**다. 대역폭 `1/dt`에 걸쳐 적분하면
`dt` 시간 동안 분산은

```
Var = σ² · dt          ← 맞음
```

가 된다. **`(σ·dt)²`가 아니다.** 코드에는 이 실수가 있었고,
`dt = 0.01`에서 `Q`가 **100배 작았다.** 결과는 "필터가 자기 자세를 과신해서
중력 업데이트가 기울기를 못 고침"이었다. 증상이 원인과 전혀 안 닮아서
찾기 어려웠다.

```python
Q[3:6, 3:6]     = np.eye(3) * config.ACCEL_NOISE_DENSITY**2 * dt
Q[6:9, 6:9]     = np.eye(3) * config.GYRO_NOISE_DENSITY**2 * dt
Q[9:12, 9:12]   = np.eye(3) * config.GYRO_BIAS_RANDOM_WALK**2 * dt
Q[12:15, 12:15] = np.eye(3) * config.ACCEL_BIAS_RANDOM_WALK**2 * dt
```

> **단위로 검산하는 습관.** `σ_g` = rad/s/√Hz = rad/√s.
> `σ_g²·dt` = rad²/s · s = **rad²** ✓ (각도 분산). 맞다.
> `(σ_g·dt)²` = rad²·s → 단위가 안 맞는다. 단위만 봐도 잡혔을 버그다.

### 7.5 공분산 전파

```
P ← F P Fᵀ + Q
```

`p`, `v` 행에 `Q`가 직접 없는 것에 주의. 위치 불확실성은 오직 `F`를 통해
속도 불확실성에서 흘러들어온다. 그게 물리적으로 맞다 — 위치에는 자체
잡음원이 없다.

## 8. 관측 5종 — 전체 유도

모든 관측은 같은 틀을 쓴다. 필요한 건 세 가지뿐이다:

- `z` — 실제로 측정한 값
- `h(x)` — 명목상태로부터 예측한 측정값
- `H = ∂h/∂δx` — 오차상태에 대한 야코비안 (15열)

그리고 `y = z − h ≈ H δx`가 성립해야 한다.
**이 근사가 성립하는지를 `test_filter.py`가 수치미분으로 검사한다.**

공통으로 쓰는 결과 두 개를 먼저 유도한다.

**(A) 바디속도의 야코비안.** `v_body = Rᵀ v`.
국소 관례에서 `R → R(I+[δθ]ₓ)` 이므로 `Rᵀ → (I−[δθ]ₓ)Rᵀ`:

```
δ(v_body) = Rᵀ δv − [δθ]ₓ Rᵀv = Rᵀ δv + [Rᵀv]ₓ δθ
```

→ `∂/∂δv = Rᵀ`, `∂/∂δθ = skew(v_body)`

**(B) 바디에서 본 중력의 야코비안.** `g_body = Rᵀ g_up`. 같은 계산으로

→ `∂/∂δθ = skew(g_body)`

---

### 8.1 휠 속도 — `update_wheel_velocity`

**무엇을 아는가**: 바퀴가 도는 속도로부터 전진속도를 안다.
**왜 x만 관측하는가**: 옆·위 방향은 바퀴가 말해줄 수 없다. 그건 NHC의 일.

```
z = v_wheel                      (스칼라, 바퀴 평균 m/s)
h = (Rᵀ v)_x
H = [ 0 | Rᵀ[0,:] | skew(Rᵀv)[0,:] | 0 | 0 ]        (1×15)
R = σ_wheel²
```

`σ_wheel`은 "바퀴가 말하는 속도를 얼마나 못 믿는가"이며, 슬립이
여기 들어간다. 미끄러운 지면일수록 커야 한다.

> **현재 값:** 직진 줄자 로그로 `σ_wheel = 0.012 m/s`를 정했다. 회전하면
> 스키드 스크럽 때문에 모델이 약해져 `|yaw_rate|`에 따라 R을 키운다.
> 회전 중 위치 정확도는 아직 외부 ground truth로 검증하지 못했다.

### 8.2 NHC (비홀로노믹 구속) — `update_nhc`

**공짜 관측이다.** 센서가 아니라 물리적 사실에서 온다:

> 바퀴 달린 로버는 **옆으로 미끄러지지 않고**, **날지 않는다.**

```
z = [0, 0]
h = [(Rᵀv)_y , (Rᵀv)_z]
H = ⎡ 0 | Rᵀ[1,:] | skew(Rᵀv)[1,:] | 0 | 0 ⎤        (2×15)
    ⎣ 0 | Rᵀ[2,:] | skew(Rᵀv)[2,:] | 0 | 0 ⎦
```

이건 강력하다. 속도 3차원 중 2개를 묶어버리므로, 자이로 표류로 생긴
횡방향 속도 오차가 계속 눌린다.

**적응형 R.** 스키드스티어는 회전할 때 **실제로 옆으로 미끄러진다.**
그때도 `v_y=0`을 강하게 주장하면 필터가 거짓말을 믿는다. 그래서 회전이
빠를수록 구속을 느슨하게 한다:

```
σ_vy² = σ_base² + (κ·|ω_z|)²
```

`κ = R_NHC_VY_TURN_GAIN`. 직진(`ω_z≈0`)에서는 원래대로 빡빡하고,
급회전에서는 자동으로 풀린다.

### 8.3 ZUPT (영속도 갱신) — `update_zupt`

**로버가 서 있다면 속도는 0이다.** 세 성분 모두.

```
z = [0,0,0]
h = v
H = [ 0 | I | 0 | 0 | 0 ]        (3×15)
```

야코비안이 가장 단순하다 — 속도가 상태에 그대로 있으니까.

효과는 극적이다. 정지 중 IMU 적분이 만들어낸 속도 오차를 매번 0으로
끌어내리므로, **위치 오차가 자라지 못한다.** 실측: 20초 정지에서
드리프트 5.3 mm.

### 8.4 중력/기울기 — `update_gravity`

**정지 상태에서 가속도계가 읽는 것은 중력뿐이다.** 그 방향이 곧
절대 roll/pitch다. (yaw는 중력으로 알 수 없다 — §9)

센서 모델 `accel_raw = Rᵀ g_up + ba`에서:

```
y = accel_raw − ba − Rᵀ g_up
  = skew(g_body)·δθ  +  I·δba

H = [ 0 | 0 | skew(g_body) | 0 | I ]        (3×15)
```

> **`δba` 블록의 부호가 `+I`다.** 코드에 `−I`로 적혀 있었고
> 2026-09-06에 고쳤다. 정지 로그에서는 기울기와 가속도계 바이어스가
> 거의 구분이 안 되어(§9 관측가능성) 드리프트가 5.28 → 5.35 mm로 밖에
> 안 변했지만, 바이어스 추정을 반대로 밀고 있었다.
> 이런 부류를 사람 눈으로 잡을 수 없어서 `test_filter.py`를 만들었다.

**두 개의 게이트, 둘 다 필요하다.**

1. `| ‖accel‖ − g | < 0.5` — 가속 중이면 읽은 게 중력만이 아니다.
2. `|ω_z| < 0.1 rad/s` — **회전 중이면 안 된다.**

2번이 미묘하다. 원심가속도는 중력과 **수직**이라 `‖accel‖`을 거의 안
바꾼다. 그래서 1번 게이트를 그냥 통과한다. 그런데 필터는 그걸 **기울기로
읽는다.** 가짜 roll이 공분산을 타고 yaw로 새고, 방위가 망가진다.

실측(원 궤적 시뮬): 게이트 없음 → yaw −48.3°, 위치 0.71 m.
게이트 추가 → yaw +0.17°, 위치 0.003 m.

게이트를 `update_gravity()` **안에** 둔 이유가 이것이다. 호출자가 잊을 수
없게. (`model_gravity()`는 순수 수학, `update_gravity()`가 게이트 담당.)

### 8.5 ZARU (영각속도 갱신) — `update_zaru`

**이 필터에서 가장 중요한 관측이다.**

로버가 서 있으면 참 각속도는 0이다. 그러면 자이로가 읽는 값은
**정의상 바이어스 그 자체**다.

```
gyro_raw = 0 + bg + n    →    z = gyro_raw,  h = bg

H = [ 0 | 0 | 0 | I | 0 ]        (3×15)
```

`bg`를 **직접** 관측한다. 이게 왜 결정적인가:

> §4.3에서 봤듯 위치 오차는 `g·b_g·T³/6`이다. `b_g`를 없애는 것이
> 오도메트리 정확도에 가장 큰 레버리지이고, **ZARU가 그걸 하는 유일한
> 수단이다.**

그리고 여기서 이 프로젝트의 근본 제약이 나온다:

> **ZARU는 정지해야만 동작한다. 그러므로 계속 달리면 바이어스를 제거할
> 방법이 없다.** 실측 바이어스 3.7 °/s로 20초를 쉬지 않고 달리면 yaw가
> 약 20° 표류한다. **미션 주행 프로파일에 주기적 정지가 필요하다.**
> `test_filter.py`의 테스트 8(정지 있음)/9(정지 없음)가 이 사실을 고정한다.

### 8.6 정지 판정 — 이 모든 게 걸려 있는 스위치

ZUPT와 ZARU는 "지금 정지"라는 판정에 의존한다. 잘못 켜지면 움직이는데
0이라고 우기게 되고, 안 켜지면 바이어스를 영영 못 잡는다.

**처음에 `|gyro| < 임계값`으로 했고, 실기에서 한 번도 안 걸렸다.**

```
정지 상태 실측:  |gyro| 평균 0.0807 rad/s   임계값 0.02
              축별 std [0.0036, 0.0016, 0.0012]
```

로버는 완벽히 정지해 있었다. std가 그걸 증명한다. 그런데 바이어스가
0.08 rad/s여서 크기(magnitude)는 임계값의 4배였다. 2000 사이클 중 **0회**
발동, yaw는 20초에 31° 표류.

**닭과 달걀이다**: 바이어스를 없애려면 ZARU가 필요하고, ZARU가 걸리려면
자이로가 작아 보여야 하고, 자이로는 바이어스를 없애야 작아진다.

**해법: "값이 0에 가까운가"를 묻지 말고 "값이 변하고 있는가"를 묻는다.**

정지한 자이로는 *틀린 값을 일정하게* 읽는다. 움직이는 자이로는 *변하는 값*을
읽는다. **표준편차는 그 차이를 보고, 바이어스에 전혀 영향받지 않는다.**

현재 판정 조건 (`StillnessDetector`, 20샘플 창):

1. 모든 바퀴 속도 < 0.02 rad/s
2. **자이로 축별 std < 0.030 rad/s** ← 핵심
3. 가속도 축별 std < 0.250 m/s²
4. `|‖accel‖ − g| < 0.40`

결과: 발동률 0 % → **95.8 %**, 드리프트 31° → 0.03°.

> **같은 함정을 두 번 팠다.** 고치면서 "바이어스 보정된 크기" 검사를
> 추가했는데, `bg`는 ZARU가 수렴하기 훨씬 전에 다른 업데이트(바퀴·NHC·중력)
> 때문에 이미 0이 아니게 된다. 그래서 **쓰레기 바이어스 값으로 검사가
> 켜져서** 정작 그걸 고칠 업데이트를 차단했다. 1981개 중 1960개를 기각.
> 제거했다. 바퀴 검사 + std 검사면 충분하다 — 바퀴가 멈춘 채로 로버가
> 회전할 수는 없다.

## 9. 관측가능성 — 무엇이 언제 보이는가

**관측가능성(observability)**: 어떤 상태가 관측으로부터 결정될 수 있는가.
관측 불가능한 상태는 아무리 좋은 필터로도 못 잡는다. 필터를 탓하기 전에
이 표를 봐야 한다.

| 상태 | 정지 중 | 직진 중 | 회전 중 |
|---|---|---|---|
| `v` (속도) | ✅ ZUPT | ✅ 휠 + NHC | ✅ |
| `roll, pitch` | ✅ 중력 | ⚠️ 게이트 통과 시 | ❌ 게이트 차단 |
| **`yaw`** | ❌ | ❌ | ❌ |
| `bg` (자이로 바이어스) | ✅ **ZARU** | ❌ | ❌ |
| `ba` (가속도계 바이어스) | ❌ 기울기와 축퇴 | ⚠️ 약하게 | ⚠️ |
| `p` (위치) | — | ❌ 적분값일 뿐 | ❌ |

여기서 읽어야 할 것 셋:

**1. yaw는 어디서도 관측되지 않는다.**
중력은 수직축 정보를 못 준다 (z축 회전은 중력 방향을 안 바꾼다).
바퀴는 스키드 때문에 못 믿는다. 그래서 **yaw는 순수한 추측항법**이고,
오차는 단조 증가한다. 이걸 끊으려면 외부 기준(자력계, 태양센서, 비전
랜드마크)이 필요하다. 이게 P1 이후 로드맵의 근거다.

**2. `bg`는 정지 중에만 보인다.** §8.5의 결론.

**3. `ba`는 정지 중에 기울기와 구분되지 않는다.**
가속도계가 `[0.1, 0, 9.8]`을 읽었을 때, 그게 "기울었다"인지 "x축
바이어스가 있다"인지 정지 상태에서는 **원리적으로 알 수 없다.**
가속해야 둘이 분리된다.

> 이것이 §8.4의 부호 버그가 정지 로그에서 5.28 vs 5.35 mm로밖에 안
> 나타난 이유다. 관측 불가능한 방향으로는 잘못 밀어도 티가 안 난다.
> **테스트가 실측 성능만 보면 이런 버그를 절대 못 잡는다.**
> 그래서 수학 자체를 검사해야 한다.

### 위치 오차는 왜 유계가 될 수 없는가

`p`는 어떤 관측에도 직접 등장하지 않는다 (`H`의 `δp` 열이 전부 0이다).
위치는 오직 속도의 적분으로만 결정된다. **오도메트리에 위치 관측이 없는
한 위치 오차는 유계가 되지 않는다.** 우리가 하는 일은 속도와 자세 오차를
최대한 눌러서 증가율을 낮추는 것뿐이다.
