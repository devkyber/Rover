## 0. 모터 스펙 중 코드에 들어간 숫자

| 항목 | 값 | 어디에 쓰이나 |
|---|---|---|
| 해상도 | **4096 pulse/rev** | `POSITION_TO_RAD = 2π/4096` |
| Model Number | **1040** | `dxl_tool.py` / `dxl_tool.py`가 모터 확인용 |
| 감속비 | 353.5 : 1 | — |
| Stall Torque | **3.3 N·m** (24 V, 0.7 A, **4.714 N·m/A**) | ★ 아래 참고 |
| 무부하 속도 | 31 rev/min (24 V) | 무부하 사양 환산; 적재 실차 상한이 아님 |
| 입력 전압 | **24.0 V** 권장 | 12 V로는 토크가 안 나옴 |
| 무게 | 82 g | 4개 = 328 g (3 kg 제약 대비) |
| 대기 전류 | 36 mA | 전류 기반 슬립검출의 바닥값 |

★ **`4.714 [N·m/A]`가 P2(슬립 검출)의 핵심 숫자입니다.** `Present Current`(126)를 읽고 있으니
`토크 = 전류[A] × 4.714`로 **바퀴에 걸리는 부하를 직접 추정**할 수 있습니다.
바퀴가 헛돌면 전류가 떨어지고, 걸리면 치솟습니다. 지금은 값을 로깅만 하고 필터가 안 씁니다.

**무부하 사양 환산속도**: 31 rev/min = 0.517 rev/s, 실측 바퀴 반지름
62.5 mm이므로 `0.517 × 2π × 0.0625 ≈ 0.203 m/s`. ROBOTIS가 24 V 무부하에서
측정한 모터축 수치이며, 노트북·차체 하중과 바닥저항이 있는 로버의 지속
최고속도가 아니다. 실제 값은 full-command 직선 로그의 정상상태 구간으로 측정한다.
기본 `Velocity Limit(44)=135`의 환산은 약 `0.2023 m/s`다. 현재 시뮬레이터의
외측바퀴 요구 최대값은 `0.1985 m/s`로 이 command 범위 안에 있다.

## 1. 반드시 확인해야 하는 EEPROM 설정

EEPROM은 **Torque Enable(64)이 0일 때만** 쓸 수 있습니다. 전원을 꺼도 유지됩니다.

| 주소 | 이름 | 공장 기본값 | **우리가 원하는 값** | 이유 |
|---|---|---|---|---|
| 7 | ID | 1 | **1, 2** | 중복되면 통신 오류 |
| 8 | Baud Rate | 1 (57,600) | **7 (4.5 Mbps)** ✅설정함 | 100 Hz 달성 |
| 9 | Return Delay Time | **250** (=500 µs) | **0** ✅설정함 | 모터당 500 µs 낭비 제거 |
| 10 | Drive Mode | 0 | **0** (그대로) | 아래 ⚠️ |
| 11 | Operating Mode | **3** (Position) | **1 (Velocity)** ⚠️미설정 | 아래 ⚠️⚠️ |
| 44 | Velocity Limit | 135 | 그대로 | 135 × 0.229 = 30.9 rev/min |
| 38 | Current Limit | 689 | 그대로 | 689 × 1.34 mA = 0.923 A |
| 31 | Temperature Limit | 80 °C | 그대로 | 절대 올리지 말 것 |

### ⚠️⚠️ Operating Mode(11) — 아직 안 하신 것 같습니다

**기본값이 3(Position Control Mode)입니다.** 이 모드는 0~360° 범위 안에서만 움직이므로
**바퀴처럼 계속 돌지 않습니다.** 주행하려면 **1 (Velocity Control Mode)** 로 바꿔야 합니다.

지금은 읽기만 하니까 상관없지만, 모터를 돌리는 순간 막힙니다. `dxl_tool.py`가 이걸 잡아냅니다.

### ⚠️ Drive Mode(10) bit 0 — WHEEL_SIGN과 중복 주의

bit 0 = Normal/Reverse. 이걸 1로 하면 **모터 안에서** CW/CCW가 뒤집히고,
`Present Position`·`Present Velocity`의 부호도 같이 뒤집힙니다.

우리는 오른쪽 바퀴 미러 장착을 **`config.WHEEL_SIGN = [+1, -1]`로 소프트웨어에서** 처리합니다.
**둘 다 하면 서로 상쇄되어 아무 일도 안 일어납니다.** 하나만 쓰세요.
소프트웨어 쪽을 권장 — 모터를 공장 기본값으로 두면 모터를 바꿔 껴도 `config.py` 한 줄만 고치면 됩니다.
`dxl_tool.py`가 이 중복도 검사합니다.

## 2. 매 사이클 읽는 것 (`dxl_reader.py`)

| 주소 | 크기 | 이름 | 단위 | 부호 |
|---|---|---|---|---|
| 126 | 2 | Present Current | **1.34 mA** | signed int16 |
| 128 | 4 | Present Velocity | **0.229 rev/min** | signed int32 |
| 132 | 4 | Present Position | **1 pulse** (0.088°) | unsigned int32 |

126~135 = **10바이트 연속** → Sync Read 한 방. `config.SYNC_READ_START/LEN`.

> 부호 변환은 SDK가 안 해줍니다. 음수는 2의 보수입니다. `dxl_reader.py`에서 직접 뒤집습니다.

### 나중에 붙일 만한 것: Realtime Tick(120)

주소 120, 2바이트, **1 ms 단위 모터 내부 시계**(0~32,767 순환).

**IMU-엔코더 시각동기(미완료 7번)에 쓸 수 있습니다.** 지금은 PC의 `time.monotonic()`으로
타임스탬프를 찍는데, 그건 "패킷이 PC에 도착한 시각"이지 "모터가 측정한 시각"이 아닙니다.

블록을 **120~135(16바이트)** 로 넓히면 Realtime Tick + PWM + 전류 + 속도 + 위치를 한 번에 받습니다.
4.5 Mbps에서 6바이트 추가는 무시할 만합니다. 실기 왕복시간 측정 후 판단하면 됩니다.

## 3. 문제 생겼을 때 읽어볼 것

| 주소 | 이름 | 의미 |
|---|---|---|
| 70 | **Hardware Error Status** | 아래 비트표. 여기 값이 있으면 REBOOT 필요 |
| 63 | Shutdown | 어떤 오류에서 토크를 끊을지 설정 (기본 52) |
| 144 | Present Input Voltage | 0.1 V 단위. **240이면 24.0 V** |
| 146 | Present Temperature | 1 °C 단위 |
| 122 | Moving | 움직임 여부 (Moving Threshold(24) 기준) |
| 123 | Moving Status | 목표 추종 실패(Following Error) 등 |

### Hardware Error Status(70) 비트

| 비트 | 의미 | 로버에서 흔한 원인 |
|---|---|---|
| 0x01 | Input Voltage Error | 배터리 방전, 전압 강하 |
| 0x04 | Overheating Error | 80 °C 초과. **20분 이상 식힐 것** |
| 0x08 | Motor Encoder Error | 엔코더 고장 |
| 0x10 | Electrical Shock Error | 전원 부족/전기 충격 |
| 0x20 | **Overload Error** | **바퀴 고착(stuck).** 슬립검출과 직결 |

**오류가 뜨면 Torque Enable(64)이 0으로 떨어지고, REBOOT 전엔 다시 켜지지 않습니다.**
펌웨어 v41+에서는 LED가 1초마다 깜빡입니다.

> `0x20 Overload`는 P2에서 **"바퀴가 완전히 박혔다"의 확정 신호**로 쓸 수 있습니다.
> 전류 기반 추정보다 확실합니다.

## 4. 안전장치 — Bus Watchdog(98)

**단위 20 ms, 범위 1~127. 기본값 0(비활성).**

Torque가 켜진 상태에서 이 시간만큼 패킷이 안 오면 **모터가 스스로 정지**합니다.
정지 후 값이 `-1`이 되고, 0을 다시 써야 풀립니다.

지금 벤치에서는 필요 없지만, **로버가 자율주행할 때는 반드시 켜야 합니다.**
Jetson이 죽거나 USB가 빠졌을 때 바퀴가 계속 도는 걸 막는 유일한 장치입니다.
100 Hz 루프면 `5`(100 ms) 정도가 적당합니다.

## 5. 지금은 안 쓰지만 알아둘 것

- **Indirect Address(168~)** — 떨어져 있는 주소를 연속처럼 묶어 한 번에 Sync Read.
  지금은 126~135가 이미 연속이라 필요 없습니다. 나중에 Hardware Error Status(70)까지
  같이 읽고 싶어지면 이걸로 붙이면 됩니다. RAM 영역(64~661)만 지정 가능.
- **Secondary(Shadow) ID(12)** — 여러 모터에 같은 보조 ID를 줘서 한 번에 명령.
  4륜에 같은 속도를 줄 때 유용할 수 있지만, **Status Packet이 안 옵니다.**
- **Startup Configuration(60)** — 펌웨어 v45+. 전원 인가 시 자동 Torque On.
  로버에서는 **위험**할 수 있으니 기본값 0 유지 권장.
- **Homing Offset(20)** — 위치 0점 조정. 바퀴에는 의미 없음(연속 회전).

```python
from dynamixel_sdk import PortHandler, PacketHandler, GroupSyncRead, COMM_SUCCESS
```

**단 하나 남은 외부 의존성은 `pyserial`이다.** SDK의 `port_handler.py`가 `import serial`을 한다.

```bash
pip install pyserial numpy matplotlib
```

동작 확인:

```bash
python rover/sdk_path.py
```

`dynamixel_sdk imported from: ...\rover\vendor\dynamixel_sdk\__init__.py` 가 나오면 성공.

## 8. 우리가 실제로 쓰는 SDK 호출 (그리고 그것뿐)

### 포트 열기

```python
port_h = PortHandler("COM3")        # 리눅스면 "/dev/ttyUSB0"
pkt_h  = PacketHandler(2.0)         # 반드시 2.0

port_h.openPort()                   # -> True/False
port_h.setBaudRate(1000000)         # -> True/False
```

`openPort()`가 False면 포트 이름이 틀렸거나 **다른 프로그램(DYNAMIXEL Wizard)이 잡고 있다.**

### Sync Read 준비 (한 번만)

```python
reader = GroupSyncRead(port_h, pkt_h, 126, 10)
for motor_id in [1, 2, 3, 4]:
    reader.addParam(motor_id)       # -> False 면 이미 등록된 ID
```

`GroupSyncRead` 객체는 **루프 밖에서 한 번만 만든다.** 매 사이클 새로 만들면 느려진다.

### 매 사이클 읽기

```python
result = reader.txRxPacket()        # 패킷 1개 보내고 4개 응답 받음
if result != COMM_SUCCESS:
    continue                        # 한 사이클 버리고 넘어감. 예외 던지지 말 것

for motor_id in [1, 2, 3, 4]:
    if not reader.isAvailable(motor_id, 126, 2):
        continue                    # 이 모터만 응답이 없음
    raw = reader.getData(motor_id, 126, 2)
```

**여기 함정이 세 개 있다. SDK 소스(`vendor/dynamixel_sdk/group_sync_read.py`)를 직접 읽고 확인한 것.**

- **`getData()`는 실패하면 `0`을 돌려준다.** 예외도, 에러 코드도 없다. 그런데 0은 멀쩡한 값이기도 하다
  (위치 0, 속도 0). 그래서 **`getData()` 앞에는 반드시 `isAvailable()`이 있어야 한다.**
  안 그러면 죽은 모터가 "0에 멈춰 선 바퀴"로 보인다.

- **`getData()`의 `len`은 1, 2, 4만 된다.** 다른 값(3, 10 등)을 주면 조용히 `0`을 돌려준다.
  `isAvailable(id, 126, 10)`은 범위 검사만 하므로 **True를 준다** — 그래서 더 위험하다.
  우리가 126/2, 128/4, 132/4 세 조합만 쓰는 진짜 이유가 이것이다.
  (`isAvailable`의 실제 조건은 `start ≤ addr` 이고 `addr ≤ start + blocklen − len`.)

- **모터 하나가 응답을 안 하면 그 사이클 전체가 죽는다.** `rxPacket()`은 ID를 순서대로 읽다가
  첫 실패에서 바로 `return` 하고 `last_result = False`로 둔다. 그러면 **모든 ID에 대해**
  `isAvailable()`이 False가 된다. 즉 "4개 중 3개만 받는" 상황은 존재하지 않는다.
  그래서 `dxl_reader.read_wheels()`는 하나라도 빠지면 `None`을 리턴해 사이클을 통째로 버린다
  (3개 평균을 내면 오도메트리가 조용히 틀어진다).

- `getData(id, addr, len)`는 항상 unsigned. 위의 부호 변환 필요.

### 에러 메시지 읽는 법

```python
print(pkt_h.getTxRxResult(result))    # 통신 레벨 에러 (타임아웃 등)
print(pkt_h.getRxPacketError(error))  # 모터 레벨 에러 (과부하, 과열 등)
```

디버깅할 때 `result != COMM_SUCCESS`면 무조건 `getTxRxResult(result)`를 찍어봐라.

### 포트 닫기

```python
port_h.closePort()
```

**끝. 우리는 이 6개 호출만 쓴다.** 나머지 SDK 기능(BulkRead, SyncWrite, reboot...)은 지금 안 쓴다.

## 9. ID / 포트를 모를 때 — `dxl_tool.py scan`

지금 모터 ID도 COM 포트도 확정이 안 됐다. 하드웨어 꽂자마자 이걸 먼저 돌려라:

```bash
python rover/dxl_tool.py
```

하는 일:
1. 이 PC의 모든 시리얼 포트를 나열
2. 각 포트에 대해 baud rate 6종(57600 / 115200 / 1M / 2M / 3M / 4M)을 다 시도
3. 각 baud에서 ID 0~20을 `ping`
4. 응답한 모터의 **model number**를 이름으로 변환해서 출력 (XH430-V350 = 1200)
5. 마지막에 `config.py`에 붙여넣을 3줄을 그대로 출력

`ping()`은 이렇게 생겼다:

```python
model_number, comm_result, error = pkt_h.ping(port_h, dxl_id)
```

> SDK에 `pkt_h.broadcastPing(port_h)` → `(dict{id: model}, result)`도 있다. ID를 한 번에 다 찾아 훨씬 빠르다.
> 다만 벤더링한 4.0.5 소스의 해당 함수에 `# FIXME: unreachable code` 주석이 붙어 있어서
> 신뢰도가 불확실하다. `dxl_tool.py`는 느리지만 확실한 ID별 `ping()` 루프를 쓴다.

아무것도 안 나오면 순서대로 확인:
- U2D2가 꽂혀 있는가 (장치 관리자에 COM 포트가 보이는가)
- 모터에 **24 V** 전원이 들어가는가 (XH430-V350은 12 V로는 안 돈다)
- U2D2의 **RS-485 포트**에 꽂았는가 (TTL 포트는 XC430용이다 — 우리 로버는 두 종류를 같이 쓴다)
- 데이지 체인 마지막 모터

## 9.5 ⚠️ 벤더 SDK를 고쳤다 — 4.5 Mbps 함정

**증상**: DYNAMIXEL Wizard는 모터 2개를 4.5 Mbps에서 멀쩡히 보는데,
파이썬은 **어떤 baud, 어떤 프로토콜에서도 응답 0**.

**원인**: `port_handler.py`의 `getCFlagBaud()`가 baud rate 화이트리스트로 검사하는데
**4,500,000이 그 목록에 없다.** XH430 컨트롤 테이블이 Baud Rate(8) 값 7로 공식 지원하는데도.

```
setBaudRate(4500000) -> getCFlagBaud() -> -1 -> return False
```

`setBaudRate()`가 **False를 리턴하고 아무것도 안 한다.** 포트는 이전 속도에 그대로 남는다.
반환값을 안 보면(실패가 조용하니 놓치기 쉽다) **엉뚱한 속도로 패킷을 쏘게 되고**,
멀쩡한 모터가 하나도 응답을 안 한다. 업스트림도 알고 있다 — 호출부에 `# TODO: setCustomBaudrate` 주석이 있다.

**수정**: 벤더링한 사본을 고쳤다. 자세한 내용과 재적용 방법은 [`rover/vendor/PATCHES.md`](../rover/vendor/PATCHES.md).

```python
def getCFlagBaud(self, baudrate):
    return baudrate if baudrate > 0 else -1
```

U2D2의 FTDI 칩은 divisor로 비표준 baud를 만들어낸다 (Wizard가 4.5 Mbps를 내는 방식이 그것이다).

> **교훈: `setBaudRate()`의 반환값을 반드시 확인할 것.** 이 패치가 있어도 마찬가지다.
> SDK 폴더를 새 버전으로 교체하면 이 패치가 사라진다.

## 10. 속도가 안 나올 때

`python rover/dxl_reader.py`가 왕복 시간(roundtrip)을 찍어준다. 100 Hz면 **10 ms 미만**이어야 한다.

느리면 순서대로:

> 먼저 알아야 할 것: SDK의 `rxPacket()`은 등록된 ID를 **하나씩 순서대로** 읽는다(`readRx`를 ID마다 호출).
> 그래서 왕복시간은 모터 수에 비례해서 늘어난다. "Sync Read니까 4개가 공짜"가 아니다.
> 요청은 1개 패킷으로 나가지만 응답은 4개가 차례로 돌아온다.

1. **Baud rate를 올린다.** ✅ e-Manual 확인: **기본값이 57600 bps**(주소 8, 값 1)이다.
   즉 아무것도 안 건드렸으면 지금 57600이고, 이것만으로 왕복 5~6 ms가 날아간다.
   DYNAMIXEL Wizard로 4개 다 1 Mbps(값 3) 이상으로. 선택지: 9600/57600/115200/1M/2M/3M/4M/4.5M.
2. **Return Delay Time을 0으로.** ✅ e-Manual 확인: 주소 9, **기본값 250**, 단위 **2 µs** → **500 µs 지연**.
   모터 4개면 그냥 앉아서 2 ms를 버리는 셈이다. Wizard에서 4개 다 0으로.
3. **`LATENCY_TIMER`를 줄인다.** `vendor/dynamixel_sdk/port_handler.py` 맨 위에 `LATENCY_TIMER = 16` (ms)이 있다.
   Windows에서는 여기에 더해 **장치 관리자 → 포트 → USB Serial Port → 속성 → 고급 → Latency Timer를 1 ms**로 바꿔야 실제로 빨라진다. 이게 가장 흔한 병목이다.
4. **읽는 양을 줄인다.** `config.SYNC_READ_LEN`을 10 → 8로 (128~135, 속도+위치만). 전류는 별도 저속 루프로.
5. **Fast Sync Read (0x8A)로 전환.** SDK에 `reader.fastSyncRead()`가 있다.
   X430 계열 **펌웨어 v45 이상**에서만 동작한다. 응답을 하나의 패킷으로 몰아 받아 더 빠르다.
   지원 여부가 불확실해서 지금은 일반 Sync Read를 쓴다.

## 11. 흔한 증상 → 원인

| 증상 | 원인 |
|---|---|
| `openPort()`에서 `Access is denied` 예외 | **DYNAMIXEL Wizard가 포트를 잡고 있다.** False 리턴이 아니라 pyserial 예외가 터진다 |
| Wizard는 되는데 파이썬만 응답 0 | **4.5 Mbps 함정.** 위 3.5장 |
| ping은 되는데 SyncRead가 COMM_RX_TIMEOUT | baud rate는 맞는데 `SYNC_READ_START/LEN`이 모델과 안 맞음 |
| 속도가 +4294967000 같은 값 | 부호 변환(int32) 누락 |
| 4개 중 1개만 배선 불량인데 **전부** 안 읽힘 | 정상 동작이다. SyncRead는 하나라도 빠지면 전체가 실패한다. `dxl_tool.py`로 어느 ID가 죽었는지 찾아라 |
| `getData()`가 계속 0 | `isAvailable()` 확인을 건너뛰었거나, `len`에 1/2/4가 아닌 값을 넘겼다 |
| 왕복 20 ms 이상 | 위 4장, 특히 Windows Latency Timer |
| `No module named serial` | `pip install pyserial` |
| 전류값이 예상의 2배 | XH430-**V350**은 1.34 mA/LSB, **W350**은 2.69 mA/LSB. `config.CURRENT_TO_AMP` 확인 |
